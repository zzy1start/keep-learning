# 38 · 听力自动补全：导入识别 + 联网补原文 + 同套题干复用（2026-10-26 第二轮）

> 用户原话：**「当我导入 PDF 后会自动识别，如果没有对应的英语短文，自动上网搜索核查并导入；同时对于同一月份不同套的英文听力，如果都是相同的一套听力，应该自动为未印听力题干的套卷补充完整题干，而不是说导入 PDF 上面没有印；继续做」**
>
> 上一轮（docs/37）只做到「用户给一个网页 URL → 抓正文填文本框」；联网搜索模块 js/web-search.js 已经写好但**没有接线**。本轮把它接成「自动」：
> 导入/进篇即自动识别 → 自动检索并核验听力原文 → 同套听力自动复用题干 → 都没有时如实说明原因，**不伪造题干**。
>
> 设备：Lenovo TB321FU（本轮 ADB 未连接，未做真机点击复验；证据为源码级 + Node/vm 自检 + 真实联网探测 + 构建产物）。

## 1. 为什么「导入 PDF 没印题干」是常态（本轮实网证实）

| 事实 | 证据 |
| --- | --- |
| 四六级官方卷面只印选项、不印听力题干，题干只在录音中播报 | 抓取 2023-12 六级第 1 套公开原文页（english-exam.lazynote.cn/cet6/sections/listening/2023-12-1/）：「卷面题目」块是「5.」+ A)…D) 四个选项，**没有题干**；同一页更靠后的解析块用「【题目】」补出了机构整理的题干。页面正文 102,621 字符、24 条 W:/M: 原文行 |
| 所以不能把「PDF 上没印」当成导入失败，也不能凭空编题干 | 本轮规则：题干只能来自 ①同套听力其它套已印的题干 ②原文里逐字出现的口播题干 ③公开页确实印了题干且选项能对上；三者都没有就如实提示 |
| 上一轮「应用内没有搜索引擎」的判断不再成立 | 实网探测：Bing（宽词）、百度、搜狗、360 均可用；DuckDuckGo 在本环境不可达 |

## 2. 实现

### 2.1 新模块 js/listening-autofill.js（约 1200 行，纯函数 + 编排）

接口契约见 work/listening-autofill-contract.md（冻结版）。核心：

- **同套听力指纹** paperAudioKey(paper)：题型 + 题目数 + 每题四个选项归一化文本。同一套听力被不同套卷/不同来源 PDF 印出来时指纹相等；不同听力 16 个选项全同几乎不可能。
- **同套题干复用** findStemDonors / copyStemsFromDonor：指纹相同 + 逐题选项归一化相等 + donor 题干完整 → 只补缺的题，不动选项/答案；来源记 stemSource='set' + stemFromSet。
- **run(paper, opts) 四步**（任一步失败继续下一步，全程不抛异常）：
  1. 同套共享（不联网、立即生效）；
  2. 联网补原文：collectTranscriptText → 结构化门槛 verifyTranscriptMatch → AI 审核（要求逐字英文证据句 + 切分脚本，脚本行 ≥60% 能在候选正文里逐字找到）；
  3. 题干：先从检索到的整页正文里找口播题干（extractStemsFromScript，确定性、逐字），再 AI 从原文提取（逐字校验 verifyStemInScript）；
  4. 仍缺 → 联网搜题干：AI 必须同时给出该题 4 个选项、与本卷选项 ≥3/4 归一化一致，且题干逐字出现在候选正文里，否则整题拒绝（applyStemJson）。
- **防编造三条硬规则**：证据句/题干必须能在候选正文里逐字找到；联网题干必须带选项并通过一致性校验；宁缺勿造（失败只写原因）。
- **补丁持久化**：Store.d.lsnPatch[paperId]（readPatches/writePatch/applyPatches，只补缺、幂等；共享副本 id xxx-shared-N 自动回退原 id）。
- **afterImport(papers, opts)**：导入后批量串行补全，模块级互斥，回调 onProgress/onResult/onPatch。

### 2.2 js/web-search.js：从单引擎扩成多引擎（本轮实网结论驱动）

| 实网问题 | 对策 |
| --- | --- |
| 搜索词带「Tapescript 第1套」时 Bing 返回完全无关的数学题/HTML 字符表结果 | buildQueries 改**宽词优先**：第一条不带套数（2023年12月 六级 听力原文），套数/专用词放后面；实测宽词能直接命中懒笔记/新东方整页原文 |
| 百度前几条常是文库 403/预览，完整原文在第 4-6 条 | maxPages 提到 6、maxTries 12；新增 requireMatch 主题门槛（正文不含 听力/六级/CET/Tapescript 等直接跳过并换引擎） |
| 搜狗/360 返回 HTTP 200 + 一段 window.location.replace 脚本（270 字节），正文全丢 | 新增纯函数 redirectTarget，fetchPage 自动跟一跳拿真正文 |
| 合并多页正文按字符截断会把目标篇截掉 | collectTranscriptText 新增 blocks（逐页正文）；pickBestBlock 按题号/说话人标记挑最像该篇的一页，excerptForQuestions 按 Questions 5 to 8 锚点截 18k 字符喂 AI |
| 引擎顺序 | 默认仍只用 Bing（历史行为，单测不变）；听力自动补全显式传 bing→baidu→sogou→so360，一个引擎抓不到可用正文才换下一个 |

### 2.3 js/views/listening.js + index.html（页面接线）

- index.html 第 85-88 行：web-search.js → listening-autofill.js → views/listening.js（顺序有自检断言）。
- **_shell**：_withSharedListening 之后、Picker 计数之前 applyPatches(pool, readPatches(Store))，补丁先于筛选/渲染生效。
- **_passage** 收尾 _autoFill(p)（不 await，不阻塞作答/播放）：同一篇 _autoTried 防抖，force 才重试；共享副本 _patchTarget 写回原篇 id。
- 缺原文卡片：状态行（检索中/已补入+来源 URL/AI 逐字核验/失败原因）+ 「🔄 自动联网补全原文」+ 保留原手动「补原文」入口。
- 缺题干提示条：idle / 正在补 / 已补 N 题（来源：同套第 X 套 · 原文口播 · 联网核验 · AI 原文提取）/ 没补到的原因 + 「🔎 联网补全题干」。
- **onPatch**：模块自己 writePatch，页面只做 contentBackup 同 id 条目同步（只补缺）+ Store.flush() + 局部重渲染（原文卡/答题卡/头部标签/状态行，不整页重建）。
- _stemInfo 占位口径统一到模块 stemIsPlaceholder，避免「提示条说缺 N 题、页面又渲染出题干」互相打架；写模式模糊题号规则未动。

### 2.4 js/importer.js（导入接线）

- **套别自动识别**：_detectSetEvidence 从正文找「第X套 / Set N」，同一行内排除「与第X套相同 / 未重复显示 / 只考」等指别的套的说明；用户手选优先；证据唯一才写 meta.setNo，冲突只记录不猜；导入成功弹窗显示「（正文自动识别）」+ 依据。
- **同套听力识别（入库前、纯本地）**：_linkSharedListening 用 paperAudioKey 比对全校听力篇目；同 key 且有完整题干 donor → copyStemsFromDonor + writePatch + flush（题干随正文一起落盘）；同月不同套 → 新篇 sharedListening/sharedFromSet，始终记 sameListeningAs。
- **导入后自动补全**：只把缺原文/缺题干的 cet4/cet6 篇目排队（300ms 合并批量），_persist 完成后异步调 window.ListeningAutoFill.afterImport，**不 await 阻塞导入成功弹窗**；模块 busy 最多重试 6 次；结束后仅在听力页且未播放时刷新。
- 原「N 篇听力只有题干没有原文」的 toast 改为「已自动在后台联网检索并核验原文，失败会给出原因」。

### 2.5 离线外壳 sw.js

- 预缓存补上 js/web-search.js、js/listening-autofill.js（以及 index.html 已引用但漏掉的 native-http/native-tts/audio-pack/local-tts），CACHE v18 → v19，避免 PWA 离线首开缺脚本。

## 4. 未做 / 限制

1. **官方不印的题干无法凭空获得**：题干来源只有「同套其它套已印 / 原文口播逐字 / 公开页确有印且选项一致」；三者都没有时页面会说明原因，而不是硬填。用户若要「AI 按选项还原一个题干」，需要另立需求并明确标注「AI 还原、非真题干」——本轮没有做，避免把推断当真题。
2. 检索依赖抓取搜索引擎，遇验证码/登录墙/纯前端渲染会失败；失败会给出具体原因（网络/超时/非网页/过短/无关/选项不符）。
3. 联网补原文与 AI 核验需要用户已配置 AI（默认 DeepSeek）；AI 未配置时完全不出网，只做同套题干复用与已有原文的确定性抽题干。
4. 已完成真机复验（见 §4.5，真实联网 + 真实 AI）；仍未在真机上端到端跑「导入新 PDF → 后台自动补全」（会额外写入一套测试卷，本轮未做），导入接线由单元测试覆盖。
5. PWA 旧缓存用户需刷新一次（sw cache v19 生效）。
6. 构建：work/gradle-home 是本轮为绕开沙箱对 C:\Users\zy\.gradle 的写限制而复制的工作区 Gradle 缓存（1.3GB，非交付物，可删）。
