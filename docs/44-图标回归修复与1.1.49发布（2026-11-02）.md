# 44 · 1.1.48 桌面图标/启动页回归修复与 1.1.49 发布（2026-11-02 晚）

> 用户反馈：**「现在平板是这个图案」**（附图为 Capacitor 默认蓝色 X + 网格）——桌面图标/启动页
> 不是宣传片里的 ZY 品牌标。本轮只修品牌图标链路与重新发布，不动业务代码。

## 1. 现象与现场取证

从 APK 直接抽 `mipmap-xxxhdpi/ic_launcher_foreground.png`（adaptive icon 的前景层）：

| 包 | 尺寸 / 字节 | SHA-256 | 画面 |
|---|---|---|---|
| `KeepLearning-1.1.47-lite-release.apk`（10/29 20:53 发布） | 432×432 / 31,236 B | `99ae6bb3…` | **ZY 蓝青渐变标** |
| `KeepLearning-1.1.48-lite-release.apk`（11/2 20:53 发布） | 432×432 / 15,529 B | `bd24fd38…` | **Capacitor 默认蓝色 X + 网格** |

- 开屏 splash 同理：1.1.47 是 ZY 白底（16–19 KB），1.1.48 是默认素材（3–10 KB）。
- 两个包内 `assets/public/assets/logo-lg.png` 完全一致（125,470 B，`74c202ea…`）→ **应用内 logo 没坏**，
  坏的只有 Android 桌面图标与开屏启动页。
- 1.1.48 的 `android/app/src/main/res/mipmap-*` 文件时间戳是模板自带的 **2026/9/1 6:02:36**，
  而 `android/app/src/main`、`res`、`java` 等目录是 **2026/10/29 21:01:46**。

## 2. 根因

1. 10/29 换标是**一次性手工操作**：生成/校验脚本放在 `work/logo-assets/`（`work/` 被 .gitignore），
   生成的图标直接写进本机 `android/`（`/android/` 也不入库）；仓库里没有 Android 品牌图标源文件。
2. 10/29 21:01:46 运行了 `tools/init-android.cjs`（`rm -rf android/` + `cap add android`），
   res 被 Capacitor 模板原样覆盖回默认素材。
3. `tools/init-android.cjs` 只恢复自研插件、Gradle 模板与签名配置，**不恢复图标/splash**。
4. 因此 10/29 21:01 之后重建的包（1.1.48、当天之后的 debug 包）都带默认图标；
   1.1.47 官方包构建于 10/29 20:53（早于重置），所以它的 ZY 图标是对的。

## 3. 修复

### 3.1 品牌素材入库：`native/android/brand-res/`（26 个 PNG）

- 15 个 mipmap：`mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher{, _round, _foreground}.png`
- 11 个 splash：`drawable/splash.png` + `drawable-{land,port}-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/splash.png`
- 来源：从 1.1.47 官方 debug 包内**原样提取**（与 10/29 生成字节一致），附 `README.md` 说明尺寸/由来/使用方式。

### 3.2 安装脚本：`tools/install-brand-res.cjs`

把 `native/android/brand-res/` 覆盖到 `android/app/src/main/res/`；`--check` 只校验不写文件。

### 3.3 接进重建流程：`tools/init-android.cjs`

- 新增 6.6 步「安装品牌图标/启动页」：`cap add/sync` 之后自动执行 `install-brand-res.cjs`（26 个文件）。
- 顺带修 `runNpx → runCap`：直接用当前 `node` 执行 `node_modules/@capacitor/cli/bin/capacitor`，
  不再依赖 `npx`/`npm` 在 PATH 上（本机这次就是只有 `node.exe`、没有 `npx.cmd`，旧脚本会直接失败）。

### 3.4 防回归：`tools/check-brand-res.cjs` + CI

- 校验 26 个 PNG 的**尺寸 + SHA-256 清单**（防止被默认素材或别的图替换）；
- 校验 `install-brand-res.cjs` 存在且 `init-android.cjs` 在 `cap add android` 之后调用它；
- 本机存在 `android/` 时，逐字节比对 `android res` 是否已装好品牌素材；
- CI 新增 `Check brand icons (Android launcher/splash)` 步骤。
- 先验证它能抓到本次问题：修复前运行 → **FAIL 26 项**（全是默认素材）；install 后 → 全部 PASS。

### 3.5 版本

`versionCode 73` / `versionName 1.1.49`（入库模板 `native/android/gradle-templates/app-build.gradle` + `package.json`）。
本版包含 1.1.48 的全部业务改动（docs/41 已做标记、docs/42 AI 判断修复），只多了图标/启动页修复与工具链。
