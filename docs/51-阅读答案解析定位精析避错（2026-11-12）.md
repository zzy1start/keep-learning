# 51 · 阅读解析补【定位】【精析】【避错】（2026-11-12）

> 用户反馈（两张截图）：阅读页提交后，每题解析卡只有「解析 · 待核验 / 原文依据：」两行空内容；
> 希望像官方《答案详解》（图 2）那样给出【定位】【精析】【避错】。
> 截图顶部已显示 AI 估算的本篇总分（15 分），说明 AI 已配置可用，不是「没开 AI」。
> 本轮只改网页版代码与自检：不动题库数据、不重建 APK、不升版本号。

## 1. 根因（代码事实）

### 1.1 校验层把整题丢了（模型其实返回了内容）

本轮修改前的 `js/ai.js:1029-1038` 是「全字段复合校验」，任一项不过就整题丢弃：

- `answer` 只认 0 基整数：模型返回 `"C"` 时 `Number("C") = NaN` → 整题丢弃；
- `evidence` 只做空白归一后要求 `full.includes(evidence)` 且长度 ≥ 12：模型加引号、用省略号或稍微改写 → 整题丢弃，已经写好的 `explain` 也一起丢；
- `explain` 必须非空字符串，否则整题丢弃；
- `result` 只认 `{items:[...]}`：模型返回顶层数组时静默得到 0 条；
- 丢弃没有任何日志，`error` 常为空。

而旧界面（本轮修改前 `js/views/reading.js:1297-1301`）无条件输出「解析 · 待核验　原文依据：」+
`q.explain` / `q.evidence`。`review.items` 为空 ⇒ 两个字段从未写入 ⇒ 截图里就是两行空标签。

### 1.2 失败状态粘滞（「AI 明明可用，为什么一直是待核验」）

- 旧 `_verifyCurrentReading` 开头：`if (!force && p._answerVerification) return;`；
- 导入篇对象同时挂在 `Dict.content.reading.passages` 与 `Store.d.contentBackup`——`js/importer.js:2684-2691` 存进 contentBackup 的是**同一对象引用**，`js/dict.js:26-50` 重启时再合并回 content；
- `_submitAndRender` 在写入 `p._answerVerification` 后调用 `Store.flush()`（`js/views/reading.js:532-551`），`Store.flush` 全量序列化 `Store.d`（`js/store.js:152-158`）⇒ `status:'failed'/'unavailable'` 会随篇目落盘；
- 之后每次提交 / 显示答案都命中 early-return，**永远不再核验**，除非用户手动点「AI 重新核验」。

独立复核（teammate `reading-analyst`，只读 + 内存 vm 回放旧代码）实测：控制组通过；字母答案、evidence 带省略号、
缺 explain、顶层数组四种情况结果都是 `failed + 0 条 + error=''`——与截图现象一致，旧界面无法区分原因。

## 2. 修复

### 2.1 AI 层（js/ai.js）

- **提示词重写为「答案详解」式**：`answer` 用字母 A–D；`explain` 是 2~4 句中文【精析】（题型 + 题干关键词定位 + 推理）；
  `wrong` 是逐项中文【避错】；`evidence` 必须逐字复制原文。
- **答案容错** `_readAnswerIndex`：字母 / 0 基序号；1 基序号只在能与题库答案互相印证时按 1 基解释（不静默改答案）；
  题库答案既认字母 `"C"` 也认数字 `2`（内置数据与导入 schema 都是数字）。
- **依据容错** `_readLocateEvidence`：先逐字（空白/弯引号/破折号归一），再按句词重合度定位；定位成功一律回填**原文原句**；
  定位失败只清空依据、保留答案 + 精析（旧实现整题丢）。
- **精析校验**：`explain` 必须非空且含中文，避免英文占位被当成【精析】。
- **避错过滤** `_readWrongOptions`：剔除非选项字母、非中文、正确项；支持对象与数组两种写法。
- **返回形状/下标容错**：接受顶层数组；`index` 支持全局下标 / 原卷题号（`number`）/ 批内 0 基 / 批内 1 基——
  先看整批 indexes 落在哪个口径再统一换算（逐条猜会在 1 基时把答案挂到错题），换算与丢弃都 `console.warn`。

### 2.2 页面层（js/views/reading.js）

- `_verifyCurrentReading`：传给 AI 的是页面真实渲染的清洗后段落 `_parasOf(p)`，与定位同源；
  写回 `q._analysis = { source, location, quote, explain, wrong }`；重试时清掉旧 `_analysis`。
- early-return 只对 `verified / partial` 生效：失败 / 未配置状态下次提交自动重试（修掉「永远待核验」）。
- `_locateEvidence`：用 `_parasOf(p)` 的段/句计算「第 N 段第 M 句」，与左侧正文完全一致；
  导入数据自带 `explain + evidence` 也走同一套（徽章显示「题库解析」）。
- `_readingAnalysisHTML`：解析卡改为【解析 + 徽章】+【定位】+【原文】+【精析】+【避错】；
  用户选错的选项在避错里标「你选的」；没有解析时按原因显示（未启用 AI / 核验失败+原因 / 部分未通过 / 等待中），
  不再输出空「原文依据：」。
- **不覆盖题库答案**：与选词填空/段落匹配同一原则——题库已有答案时不改 `q.a`，只记 `q._aiAnswer`；
  卡片显示「AI 核对结果为 X，与题库答案 Y 不一致；已保留题库答案，请自行核对」，并隐藏按 AI 答案组织的【避错】
  （避免把正确答案说成错的）；题库无答案时才用 AI 答案补全。核验横幅也按冲突/未定位情况改写文案。
- **未定位的依据**不冒充【原文】：导入数据自带 evidence 若在清洗后正文定位不到，标为【依据】并注明「未能在当前正文中逐字定位，仅供参考」。
- **修改模式解析横板**（用户二次反馈「两列并排前面挤着不好看，要像答案详解第 50 题那样横板」）：
  传统阅读在修改模式下改为单列横排（`read-q-list`），每题占满整行，【定位】【原文】【精析】【避错】不再被两列挤成窄条；
  做题模式（右侧窄栏）与完形填空布局不变。
- 完形填空（cloze 四选一）保持原样，不在本轮反馈范围。

### 2.3 样式 / 缓存

- `css/modules.css:215-235` 新解析卡样式（浅色/深色走既有 CSS 变量）；`css/modules.css` 另加 `.read-q-list` 修改模式单列横板；
  `sw.js` 缓存 v31 → v33（本轮两次前端改动各升一次）。

## 4. 未做 / 已知限制

1. **没有做真实浏览器视觉复验**：本机 Edge headless 在 DSH 沙箱内报 `mojo platform_channel ... 拒绝访问`（与 docs/45 相同限制）。
   已用真实渲染代码生成静态预览 `tmp/preview/analysis-cards.html` 供人工核对；请刷新页面后实际看一眼卡片间距/换行。
2. **没有接真实 AI Key 做端到端质量评估**：精析/避错质量取决于所配模型；模型漏写 `wrong` 时该项不显示（不编造）。
3. **依据定位失败时不显示原文**（避免把模型复述当引文），解析卡会少一行「原文」或只标【依据（未定位）】；答案与精析仍保留。
4. **AI 与题库答案不一致时保留题库答案**：精析仍按 AI 的观点写（会提示分歧），【避错】按 AI 答案组织、此时不展示；
   若题库答案本身有误，请以原卷为准人工核对。
5. **已有篇目需要刷新后重新提交**（或点「AI 重新核验」）才会生成解析；AI 结果不写回 `data/` 文件。
6. 导入篇的运行时核验状态可能随 `contentBackup` 落盘（既有行为）；本轮通过「只缓存成功状态」保证失败状态不会再阻断后续核验。
7. 未重建 APK、未升版本号；下次构建 APK 时随 Web 资源一起打包。
