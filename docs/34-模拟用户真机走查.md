## 2. 走查中发现并修复的问题

### 2.1 阅读页点题型 tab 后列表全空（严重，像"题库丢了"）
- 复现：阅读 → 点「选词填空」tab → 显示"当前考试范围没有匹配题目…当前可用 3 篇"，但 3 篇实际存在。
- 根因：题型 tab 处理器生成 `this.sel = { ...(this.sel || {}), no: 'all' }`；页面初始 `sel` 为 undefined，
  切换后变成 `{no:'all'}`。`Picker.filter` 里 `sel.year/session` 缺省时按"精确匹配 undefined"处理，
  于是把所有条目筛掉。`阅读阅读理解` 11 篇此前能显示，是因为没点过题型 tab、走的是默认参数分支。
- 修复：`picker.js` 的 filter 把缺省 level/year/session/set 当作 all；`reading.js` 两处题型 tab 处理器补全默认值。
- 回归：`check-reading-nav.cjs` 新增「只有 {no:'all'} 也不能筛空」等断言（5 项全过）；真机复验 v42 截图 17。

### 2.2 Section A 空位下拉一点就触发整句长难句分析
- 复现：选词填空修改模式点空位下拉 → 弹窗打开的同时出现 toast「已选中整句，正在做长难句分析」，
  整句被黄色高亮，并会走 AI 长难句请求（每次选词都花钱）。
- 根因：段落容器的 `touchend` 把 `select` 上的点击也当作"点句取整句"（`closest('.sent')` 命中了包含 select 的句子）。
- 修复：`reading.js` 增加 `interactiveTarget()` 守卫（select/option/input/button/a/[data-special-answer]），
  touchend 与 mouseup 都先跳过；新增回归断言。真机复验 v43：下拉打开时无 toast、无整句高亮。

### 2.3 首页词书进度「掌握 0」/ 已学 126 < 掌握 161
- 根因：`mirrorToSrs` 没写 `interval`，而首页/统计用 `Store.bookProgress` 的 `interval>=21` 判掌握 → 恒 0；
  后来补 interval 时又把"定级直通 L4、没作答"的词算成掌握，出现 161 > 126。
- 修复：`interval` 仅在 **L4 且作答过** 时写 30 天（与完成页"已掌握"口径一致）；
  `_begin` 时顺便刷新一次镜像，让旧数据立即对齐。真机 v43 首页显示「126 / 3992 · 掌握 67」，
  与完成页「已学 126 · 已掌握 67」一致。

## 3. 发现但本轮未改的观察项（建议后续处理）

1. **两处「已掌握」口径不同**：统计页「学习进度 · 已掌握 0 词」统计的是生词本里手动"标为掌握"的词；
   「各词书进度 · 掌握 67」是词库 L4 且作答过的词。同名不同义，建议改为「生词本已标记」。
2. **听力篇目编号重复**：2024 年 6 月卷下同时出现内置「第 1 篇 · The Problem with Speed」与导入
   「第 1 篇 · Conversation 1」「第 2 篇 · Conversation 2」；建议内置/导入加来源标签或分组。
3. **单词学习限时 4 秒偏紧**：四个选项都是整行英文释义时，4 秒不足以读完；走查中出现一次超时自动判错。
   可考虑按选项文本长度/词长动态 4–8 秒。
4. **测试工具限制（非 App bug）**：`adb shell input text` 在中文输入法下会把英文替换成中文候选，
   因此写作/翻译的输入改用 CDP 设置 DOM 值验证；真实用户用软键盘输入不受影响。
5. **PDF 文本层遗留**：部分导入正文有 `.,If` 这类标点粘连（抽取层审计已说明），不影响空位/选项渲染。
