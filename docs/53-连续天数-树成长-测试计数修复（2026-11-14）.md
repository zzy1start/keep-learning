# 53 · 连续天数 / 树成长 / 词汇量测试计数修复（2026-11-14）

> 用户反馈（单词页截图）：
> 1. “日志更新，即今天学了第几天似乎有错误”；
> 2. “树的成长没有变化”；
> 3. “单词界面为什么是 21/3991，我之前做过词汇量测试”。
>
> 本轮按真实源码 + 工程内真机备份复现，修的是数据口径和状态迁移，不是换 UI 文案。

## 1. 根因

### 1.1 连续天数在东八区凌晨会被重置

`js/store.js` 的 `markStudy()` 原先这样算“昨天”：

```js
const y = new Date(Date.now() - 864e5).toISOString().slice(0, 10);
st.streak = st.lastStudy === y ? st.streak + 1 : 1;
```

`App.today()` 用的是**本地日历**，这里却用 `toISOString()` 取 **UTC 日期**。
在东八区（UTC+8）00:00–08:00 之间，本地“今天”减 24 小时再转 UTC，会落到**前天**：

- 本地 2026-11-14 00:30 → UTC 2026-11-13 16:30
- 再减 24h → UTC 2026-11-12 16:30 → `slice(0,10)` = `2026-11-12`

于是 `lastStudy`（2026-11-13）永远不等于 `y`（2026-11-12），连续天数被重置成 1。
白天（08:00 之后）不会触发，所以问题只在凌晨学习时出现，很像“日志/天数突然错了”。

### 1.2 树成长被旧版树“冻结”

`js/garden.js` 的成长公式在 2026 年切到了 `trackingVersion === 2`：
新树的成长度 = 累计有效学习分钟 ÷（成熟天数 × 20）。

但 `recordActivity()` 里有这一行：

```js
const tree = this.plantDay(App.today());
if (!tree || tree.trackingVersion !== 2) return;
```

旧存档里的树没有 `trackingVersion`（工程内 `debug/device-store-backup.json` 的
“枫杨 / 樱花”两棵树都没有这个字段）。同时 `plantDay()` 会优先返回
`state !== 'stump' && growth < 1` 的旧树 —— 于是：

1. 旧树一直“可继续培育”，不会种新树；
2. `recordActivity()` 又因 `trackingVersion !== 2` 直接 return；
3. 旧树的 `investedMin` 永远不增加，成长度看起来完全不动。

另外旧实现只在整轮结束时记一次时长；中途退出、逐题学习都不计入。
10 分钟学习在 90 天树种上约 +0.55%，整数百分比又会显示成 0%，进一步放大“没变化”的观感。

### 1.3 21/3991 与“我做过词汇量测试”

顶部大数字是**引擎口径的“已学”**，不是词汇量测试的估算：

- `已学` = 引擎里真正作答过（`attempts > 0`）的词；
- `已掌握` = L4 且作答过，加上“测试整带跳过”的词；
- `定级估算 3500` 是 `vocabEngine.user.vocabEstimate`，只表示测试估算的词汇量，不直接计入“已学”。

正常完成测试时，`skipBands`（如 [0,1,2,3,5]）会让 3000+ 个基础词被计入掌握/已学。
但旧实现只把 `correct/total/estimate/rate/tiers` 写进 `Store.d.vocabTest`，
**没有持久化每带正确率 / 跳过带**；引擎状态一旦丢失，就无法恢复这个口径。
能清掉 `skipBands` 的路径包括：

- “恢复新词 / 全部取消跳过”调用 `VocabEngine.releaseUnlearned()`（会清空 skipBands/bandAccuracy）；
- “学习进度”导出/导入的 `PROGRESS_FIELDS` 里**没有 `vocabEngine`**，换设备后测试估算还在（如果来自旧备份），定级却丢了；
- 旧版/迁移只留下 `bandAccuracy`，没有 `skipBands`。

工程内真机备份 `debug/device-store-backup.json` 能对上用户截图：
`vocabTest.cet6 = 35/40，estimate 3517；vocabEngine.user.vocabEstimate = 3500，
bandAccuracy = {0:1, 1:0.857, 2:1, 3:0.833, 4:0.714, 5:0.857}`。
按旧口径，只要 `skipBands` 被清空、`bandAccuracy` 又没被使用，页面就会只剩实际作答的 21 个词。

### 1.4 顺带发现：统计页“分钟”列永远是 “-”

`Store.logActivity()` 写的是 `day.seconds`，而 `ViewStats._recent14()` 读的是 `s.min`，
所以“近 14 天明细”的分钟列一直为空，看起来像日志没有更新。

### 1.5 顺带发现：7/15/30 天复习间隔在东八区会提前一天

`VocabEngine._dayIndex()` 用本地午夜的 `getTime()`，`_dateFromIndex()` 却用
`new Date(idx*DAY).toISOString()`（UTC 日期）。东八区下两者相差一天，
`+7 天` 实际得到的是 6 天后，复习/枯萎都会偏早。

## 2. 修复

### 2.1 连续天数

- `js/core.js`：新增 `App.now()`、`App.parseDay()`、`App.shiftDay()`，
  日期一律按**本地日历**平移，不经 UTC 往返。
- `js/store.js`：`markStudy()` 的“昨天”改用 `App.shiftDay(t, -1)`。
- 新增 `Store.repairStreak()`，在 `Store.load()` 时按 `days / daily / lastStudy`
  的并集重算连续天数：
  - 以今天或昨天为锚点向前数连续记录；
  - 今天还没学 → 从昨天数，不会在 00:10 打开时显示 0；
  - 隔了两天以上 → 归 0，不再显示已经过期的旧天数；
  - 存档里已经被算错的 `streak` 会在下次启动时修回来。
- 首页/欢迎弹窗在 `streak === 0` 时显示“今天还没开始学习…”，不再出现“第 0 天”；
  当累计天数大于连续天数时，首页额外显示“累计 N 天”，避免把“连续”误读成“总共第几天”。

### 2.2 树成长

- `js/garden.js` 新增 `_migrateTrees()`：
  - 旧树迁移到 `trackingVersion = 2`；
  - 把当前成长度折算成等效投入分钟（`growth × matureDays × 20`），
    与已有 `investedMin` / 旧日统计取最大值，**迁移后成长度不会倒退**；
  - 在 `plantDay()` / `refresh()` 开头调用，保证第一次学习前就完成迁移。
- `recordActivity()` 迁移后不再被 `trackingVersion !== 2` 挡住；成长度改为只增不减。
- `js/views/vocab.js` 新增 `_takeSeconds() / _logStudyTick()`：
  - 每答一题（选择、自评、拼写、跳过、看答案）记录一次**增量**学习时长；
  - 不再等整轮结束，中途退出也有成长；
  - `Store.logStudyTime()` 只加 `day.seconds` 和树成长，不增加单词/听力等次数。
- 为逐题记录避免每答一题就 flush 整个存档：`Garden.recordActivity()` 不再自己 flush，
  由 `Store.logStudyTime()` 的 debounce save 或 `Store.logActivity()` 的结尾 flush 落盘。
- `Garden.growthPercent()` 在 <10% 时保留 1 位小数（0.3% 不再显示成 0%）。

### 2.3 词汇量测试计数

- `js/views/vocab.js`：
  - 测试完成时把 `placement`（每带正确率、跳过带、起点带、估算、抽样答对词）
    一并写进 `Store.d.vocabTest[bookId]`；
  - `_restorePlacementFromTest()` 在词书页渲染前自动恢复：
    引擎没有 skipBands/bandPlacement，但测试里有 placement → 重新 `applyPlacement`；
  - 只有 `bandAccuracy`、没有 `skipBands` 时，按 ≥80% 的带反推跳过带
    （`VocabEngine.effectiveSkipBands()`）；
  - `_engineCounts()` 同样用 `skipBands ∪ bandAccuracy≥80%` 统计“测试跳过”，
    练过/降级也不会掉数；
  - “全部从头学”按钮现在真的调用 `releaseUnlearned()` 并写 `placementDisabled`，
    与按钮文案一致；
  - 只剩估算、没有跳过带时，标签改为“测试估算（未跳过） 3500”，
    并明确提示“当前没有启用测试跳过已知词，所以已学只统计真正学过的词”；
  - 同时给出“按测试估算恢复”按钮：逐频带结果没保存时，按整体估算把最容易的
    整带标为“测试已认识”（保留最难一带），可随时用“恢复新词”撤销；
  - 用户主动取消定级后 `placementDisabled = true`，不会下次渲染又自动恢复。
- `js/vocab-engine.js`：
  - 新增 `effectiveSkipBands(user)` / `startBandFromAccuracy(user)`；
  - `releaseUnlearned()` 清空定级时保留 `vocabEstimate`（测试结论），
    但写 `vocabTest[bookId].placementDisabled = true`。
- `js/store.js`：
  - `PROGRESS_FIELDS` 增加 `vocabEngine`，换设备/恢复进度不再丢引擎定级；
  - `progressBackup()` 导出前裁剪空状态、去掉进行中的 `round`（避免 wordRef 跨设备污染）；
  - `importProgress()` 导入后重置 `VocabEngine` 内存缓存。

### 2.4 统计页分钟

- `Store.dayMinutes(day)`：优先 `seconds / 60`，旧存档回退 `min`；
- `ViewStats._recent14()` 用它填“分钟”列，学习报告 PDF 一并修复。

## 4. 对用户当前数据的效果

- 连续天数：下次启动就会按 `days` 自愈；凌晨学习不再重置。
- 树成长：现有的旧树会在打开首页/第一次学习时迁移；之后每答一题立即累计时长，
  成长百分比会开始变化（<10% 显示一位小数）。
- 21/3991：
  - 如果存档里还留着 `bandAccuracy`（真机备份里有），会自动反推跳过带，
    页面按测试结果恢复“已认识”数量；
  - 如果 `bandAccuracy` 也被清掉了（例如点过“恢复新词/全部取消跳过”），
    页面会明确显示“测试估算（未跳过） 3500”，并给出
    **“按测试估算恢复”** 按钮：按整体估算把最容易的整带（约 3300 词）标为测试已认识，
    可随时用“恢复新词”撤销；想精确到逐词，重新做一次词汇量测试即可。
- 统计页“分钟”列会显示真实学习时长。
