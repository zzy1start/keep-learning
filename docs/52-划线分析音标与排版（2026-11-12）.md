# 52 · 划线分析补音标 + 词性翻译面板排版（2026-11-12）

> 用户反馈（截图）：阅读页右侧「划线分析 · 词性翻译」里选中 prevalence，
> 单词下方没有音标，只有一个孤零零的「读」按钮被吊在左侧；
> 希望**补上单词音标**并**优化排版**。
> 本轮只改网页版代码、样式与自检：不动题库数据、不重建 APK、不升版本号。

## 1. 根因（代码事实）

| 现象 | 根因 |
|---|---|
| 没有音标 | `js/views/reading.js` 的 `_anPanel()` 词性翻译分支只输出 `<div class="an-word">单词</div>`，**从未渲染过音标**。音标文本其实已经在 `_wordInfo()` 里取到了（`book.ph` → `global[0]`），但没有任何调用点输出它；`css/modules.css` 里 `.an-ph` 规则因此长期处于"有样式无标记"状态 |
| 「读」按钮位置怪 | `.an-say{margin:-24px 0 6px auto;…}` 用**负 margin + auto** 想把按钮顶到单词右侧。inline-flex 元素的 auto 横向 margin 在普通块流里不生效，结果按钮没有右移，只被负 margin 往上提，视觉上像单词下面多出来一个按钮 |
| 声音入口重复 | 标题旁「读」和底部「🔊 发音」是同一个 `data-say` 动作，面板窄时两个按钮抢空间 |
| 释义排版散 | 释义容器是内联 `style="font-size:13.5px;margin:8px 0 4px;line-height:1.7"`，与上下区块间距靠手写数字，改一处要动多处 |

历史背景：`docs/31` 记录 1.0.3 / 1.0.5 两轮曾**主动去掉**阅读词性浮窗与面板的音标（当时平板缺 IPA 字形，音标显示成方框）。
之后 1.0.5 已内置 Noto Sans 作为 `KL IPA` 字体（`css/base.css:1-5`），词汇页一直正常显示音标；本轮按用户要求把阅读面板的音标加回来。

## 2. 修复

### 2.1 音标取数与清洗（js/views/reading.js）

- 新增 `_wordPhonetic(info)`：候选顺序 **词书 `ph` → `_wordInfo().phonetic` → 内置词典 `global[0]`**；
  每个候选都过 `_phoneticText()`（去首尾 `/[]`、trim、ASCII `:`→`ː`、`'`→`ˈ`、统一包 `/…/`）。
- 词书 `ph` 常见两种脏数据：带空格的 `"/ 'prevələns /"`、空占位 `"/  /"`（cet6 里 78/3991 个词，见 `docs/37`）。
  空占位清洗后为空串，自动回退内置词典；两边都没有才显示占位文案，不编造。
- 加入生词本（`_nbWord`）与词旁浮窗（`_showWordPop`）改用同一函数，
  不再出现 `'/' + info.phonetic + '/'` 把 `/ 'prevələns /` 拼成 `// 'prevələns //` 的脏数据。

### 2.2 词性翻译面板排版（js/views/reading.js + css/modules.css）

- 单词标题改为标题行 `.an-word-h`：**单词 + 音标 + 朗读按钮**同一行、基线对齐、底部细分隔线；
  按钮用 `margin-left:auto` 靠右（去掉负 margin）。
- 释义区改 `.an-defs`，首条 `.pos-line` 不再有上内边距；底部动作区改 `.an-actions`。
- 发音入口只保留标题行一个（底部重复的「🔊 发音」移除），`+ 生词本` / `加入明日待背` / `AI 深度解析` 不变。
- 没有音标时显示「暂无音标」浅色占位，避免用户以为功能坏了。
- 词旁浮窗 `rw-head` 补音标 span（CSS `.read-word-pop .rw-head span` 早已存在，此前标记缺失）。
