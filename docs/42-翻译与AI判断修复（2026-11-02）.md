# 42 · 翻译 / 写作 / 阅读 AI 判断修复（2026-11-02 晚）

> 用户反馈：**「现在翻译的ai识别有问题，建议检查一下以及其他的ai判断」**（无线调试已开启）。
> 本轮只修 AI 调用链与判分，不动题库、不改 UI 结构、不换用户选择的模型。

## 1. 现场证据（真机 Lenovo TB321FU）

- 打开翻译页，用户 666 字译文（天宫空间站）对应的结果对象：
  `{ gradingFailed: true, errMsg: "翻译批改未完成：timeout" }`。
- 用同一条译文复现：**61.3 秒**后报 `timeout`。
- 给原生 HTTP 桥放宽到 300 秒后，同一请求返回 200，但正文为空：
  `finish_reason=length`（思考 token 吃光了 4000 的输出预算）。
- `GET /models` 实测：
  - `deepseek-v4-pro` → `input_modalities: ["text"]`（**不支持图片**）
  - `deepseek-flash` → `input_modalities: ["text","image"]`
  - 因此翻译/写作「拍照上传」不是提示词问题，是当前模型看不到图片。
- 视觉模型可用性单独验证：同一张英文手写风格图，`deepseek-flash` 逐字识别正确（约 3 秒）。
- AI 翻译分数常出现「四维之和 ≠ total」或「max=30 而本题满分 20」，旧逻辑直接判整单失败：
  `AI 返回的维度得分与总分不一致，请重试`——重试大概率仍错。

## 2. 根因与修复

| # | 根因 | 修复 |
|---|---|---|
| 1 | 原生 HTTP `connect/readTimeout` 写死 60s，长批改必然被掐断 | `js/native-http.js`：connect 30s / read **300s** |
| 2 | JS 侧 AbortController 对 Capacitor 原生桥无效，超时形同虚设 | `AI.chat` 增加 `Promise.race` 守卫（timeout + 200ms），真正能结束请求 |
| 3 | 推理模型思考 token 计入 max_tokens，4000 常返回空正文 | 默认 8000；翻译/写作/阅读核验 12000；重试可扩到 16000 |
| 4 | 当前模型不支持图片，API 不报错但回答"无法识别" | `AI.listModels()` 缓存能力；图片请求自动路由到支持图片的模型（优先 flash/vision/vl/omni），结果里写明「已自动改用 xxx」 |
| 5 | 翻译分数硬校验过严，轻微不一致就整单失败 | `normalizeTranslationScore`：缺字段才失败；满分不同/四维和不一致时等比缩放到本题满分与 total |
| 6 | 只上传照片时 input 为空，完整性检查按空字符串算 → 0 分 | 有 `ocrText` 时用识别文本参与 coverage/chrF |
| 7 | JSON 偶尔带裸换行/尾逗号/截断 | `response_format: json_object`（不支持则降级）；`_repairJSON` 逐字符修复字符串内换行、尾逗号、未闭合括号 |
| 8 | 长请求重试不识别 `timeout` / 连接中断 | 重试表加入 timeout / timed out / 连接被中断 / ECONNRESET / broken pipe；首次失败后下次关闭 response_format 再试 |

## 3. 改动的文件

- `js/native-http.js`：超时放宽 + 注释说明。
- `js/ai.js`：
  - `AI_TIMEOUT_MS=180000` / `AI_HEAVY_TIMEOUT_MS=300000` / `AI_DEFAULT_MAX_TOKENS=8000` / `AI_MAX_OUTPUT_TOKENS=16000`；
  - `listModels()` / `resolveModel()` 视觉模型自动路由；
  - `json()` 加 response_format + 降级；`_repairJSON` 重写；`jsonRetry` 重试表与 jsonMode 降级；
  - `normalizeTranslationScore()` 替代原来的硬校验；
  - 翻译/写作/阅读核验/查词/长难句/出题的预算同步提高；
  - 失败信息把原生 "Software caused connection abort" 翻译成可读中文。
- `js/views/writing.js`：评分结果里显示「照片识别结果」与「模型说明」（翻译页复用同一个 gradeHTML）。
- `js/views/settings.js`：提示改为"当前模型只支持文本时会自动改用同接口的视觉模型"，不再让用户以为必须手动换模型。
- `tools/check-ai-plumbing.cjs`：新增 8 项假 fetch 自检（预算、视觉路由、超时、重试、归一化、JSON 修复、源码接线）。
- `tools/check-kaoyan-api.cjs`：分数一致性断言从"必须报错"改为"必须自动归一化"。

## 5. 已知限制

- 推理型模型批改长文需要 **1-2 分钟**，这是模型侧耗时；现在不会再被 60s 掐断，但等待时间仍长。
- 图片识别质量取决于拍照清晰度；识别结果会在界面显示，用户可核对。
- `/models` 拉取失败时不会强行切模型，会回退到原模型并在失败信息里说明。
- 仍建议在设置里选支持图片的模型（如 deepseek-flash）；自动路由只是兜底。
