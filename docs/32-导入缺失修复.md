## 2. 逐条根因

### 2.1 阅读 Section A/B「10 题题干和选项全空」
- 数据事实：section-a 有 `clozeText` + `wordBank` + number/答案；section-b 有 `statement` + 段落 letter；
  但通用字段 `q.q`/`opts` 为空。
- 原因：AI 的 reading schema 只要求 traditional 的 `q`/`opts`；A/B 按题型语义返回
  number/statement/a/explain/evidence。阅读页按特殊字段能显示，但通用 AI 核对
  （`js/ai.js verifyReading` 读 `q.q/opts`）与统计拿到的是空。
- 修复：入库前补全，不编造——A 的 q 取 `clozeText` 中包含该空的整句、opts 取词库；
  B 的 q 取 `statement`、opts 取段落字母。

### 2.2 听力 Questions 1-4 / 5-8「各缺 4 个题干」
- 证据：`debug/text-set1.txt` 第 15–37 行，四六级卷面**只印 A)–D) 选项，不印题干**（题干只在录音里）。
  两份源 PDF 都是这个格式。
- AI 行为不一致：Q1–8 留空、Q9 起写 `q:"Question 9"`、Q16–25 写 `"16."` 纯题号占位——都不是原文题干。
- 修复：三类占位统一清掉；原文确实印了题干才回填；没有则 `q=""` + `stemMissing:true`。
  UI 文案改为"卷面未印题干（只在录音中播报）"。**不伪造题干**。

### 2.3 set3 Passage Two 第 55 题选项为空
- 源文本第 286–290 行四选项齐全。旧 APK 数据 `opts: []`；当前仓库 `buildBatches/repairFromSource`
  已能在离线复现中保证 Q51–55 同批并回填 Q55（verifier 复现并保留为回归断言）。
- 本轮同时发现并修复**真实批次缺陷**：旧代码 set1 的切点 26273 落在 Q53 选项 B/C 之间
  （页脚空行），导致 Q53 只能解析到 2 个选项——与 Q55 `opts:[]` 同类；pipeline-fix 已修。
- 加固：入库前仍按题号从原文回填缺选项/缺题（覆盖 legacy 路径、校验失败仍并入结果的情况）。

### 2.4 新发现：Part Ⅲ（Unicode 罗马数字）导致阅读模块被错标成 listening
- 真实 set1 文本第 106 行是 `Part  Ⅲ  Reading Comprehension`（U+2162），而 `HEADING_RE` 只认 ASCII `[ivx]+`；
  `Part Ⅲ` 不被当成结构标题 → 阅读 Section 的模块继承沿用 Part II 的 listening。
- 同时 `buildBatches` 的 `flush()` 合并批次时没把 `cur.module` 传给 `pushBatch`，后者用标题重新猜模块，
  Section/Questions 这类小标题永远猜成 reading——两个问题叠加后，听力/阅读批次互相错标，
  表现为「听力批里是阅读原文 → OPTIONS_NOT_4 校验失败」「阅读批里是听力原文」。
- 修复：`HEADING_RE` 支持 U+2160–U+217F 罗马数字（用负向前瞻收尾，避免 \b 对非 ASCII 失效）；
  `flush()` 显式传 `cur.module`；并加真实 set1 文本的回归断言（26 项管道检查中的一项）。

### 2.5 新发现：AI 词库形态不一致 / 写作 schema 没有翻译变体 / 推理模型吃光输出预算
- 选词填空 AI 实际返回 `wordBank: ["alleviate","clarity",…]`（字符串数组），而校验按 `w.letter` 过滤
  → 误判 NO_WORD_BANK、批次重试/失败；入库后通用 q/opts 也补不上。
  修复：`_normalizeBatchResult` 与 `completeImportedReadingItem` 统一归一化为 `{letter, word}`。
- 写作批次的 JSON schema 只给了 essay 示例，翻译批（Part IV）AI 直接返回空 items → 翻译题导入丢失。
  修复：schema 增加 `writingType:"translation"` + `translationText` 变体，并加显式规则；缓存 promptVersion v2→v3。
- deepseek-flash 是推理型模型：导入重试时 4400/5200 max_tokens 会被思考过程吃光，返回空正文，
  真机重新导入连续 3 次失败在同一个 reading 批次。修复：`_aiSplitBatched` 首次 8000 / 重试 12000，
  `ai.js` 的截断扩容上限 5200→12000；改后真机导入通过。

### 2.6 写作 Directions 缺空格/断词
- 设备数据：`Directions:For this part,you…`、`ofdigital`、`comments,cite`。
- 抽取层证实（见 1）：文本层本来没有这些空格，只能导入后处理。
- 修复：essay 一律用原卷 Directions 逐字回填（`extractWritingPrompt`），再统一修空格与粘连：
  · 标点后补空格（`:For` / `,you`）；
  · 粘连词拆开（词典 + 原文词表 + 词形判断，避免把 `directions`/`experiences`/`workplace` 误拆）；
  · 含 URL/域名的文本跳过补空格与断词，避免把网址改坏；
  · 翻译题保留原有换行。
- 更正：早前判断"prompt 被截断"是调试输出只截 400 字符的误判；两条 essay prompt 实际完整（425/438 字符）。

## 3. 代码改动

### 3.1 `js/importer.js`（入库前统一补全，所有导入路径共用）
- `isPlaceholderStem`：识别 `Question N` / 纯题号 `16.` / `Questions 16 to 18 are based on…`。
- `completeImportedReadingItem(item)`：section-a/b 补 q/opts；traditional/cloze 从原文回填缺题干、
  缺选项、题号区间内整题缺失（a=null，避免造答案）。
- `completeImportedListeningItem(item)`：清占位、按原文回填题干、缺题干打 `stemMissing`。
- `polishImportedEnglish(text, raw, {keepLines})`：写作 Directions 空格/断词修复。
- `_normalizeBatchResult`：词库字符串数组 → `{letter,word}`；写作 schema 增加翻译变体。
- `splitGlued` 增加词典判定（`dictLooksKnown` 处理 s/es/ed/ing/ly/er/est 词形）与 dict 模式；
  修复"粘连词本身就在原文词表里导致拆不开"的问题；URL 文本不处理。
- `_commit` 三条分支接入上述补全；写作 prompt 优先用原卷 Directions。

### 3.2 `js/views/listening.js`（文案，不改数据）
- "缺题干 N" → "卷面未印题干 N"；每题提示改为"本题题干未印在卷面（只在录音中播报）"。

### 3.3 `js/import-pipeline.js`（pipeline-fix）
- `questionSpans()/cutInsideQuestion()`：切点不得落在题号行与该题选项结束之间；
  全部候选都在题块内时切到选项结束之后（题干+选项永远同批）。
- `validateBatch` 听力：空题干 → warning STEM_MISSING，占位 → STEM_PLACEHOLDER（不判 error）。
- `repairFromSource` 听力：能从原文解析出真实题干时回填（FILLED_STEM），排除 `16.A)…` 选项行。
- `tools/check-import-pipeline.cjs` 新增 5 项真实夹具测试（读 debug/text-set1.txt / text-set3src.txt）。
