# 35 · 翻译与写作：最近 5 条输入记忆（2026-10-23）

> 用户需求原话：**翻译和写作增加记忆功能，只记忆最近 5 条。**
> 本轮完成数据层、两个页面的自动记忆/查看/恢复/清空、自检与文档；
> 真机（Android 平板）触屏与软键盘验证由 Lead 并行完成。

## 1. 目标与验收

| 验收项 | 实现方式 |
|---|---|
| 两页各自独立，各只留最近 5 条 | `Store.d.translationHistory` / `Store.d.writingHistory`，`slice(0, 5)` |
| 自动记忆用户输入 | 编辑器 `oninput` → `App.debounce(..., 800)` → `Store.rememberInput` |
| 提交/保存草稿/换题/切 tab/离开页面前不丢最后几个字 | 各入口调用 `_memoFlush()`（详见第 4 节） |
| 刷新/重启后仍在 | 每次写入立即 `Store.flush()` 到 localStorage |
| 工具栏「🕘 最近记录」 | 复用 `btn btn-xs btn-gh`，点开 `App.modal` 列表 |
| 列表信息 | 第几条 · 时间 · 任务名/题目 · 文本前 30 字 + 「恢复」 |
| 恢复不自动提交 | 只回填编辑器 + 切题（能切则切）；清空旧评分 |
| 另有「清空记录」 | 二次确认后 `Store.clearInputs(kind)`，列表变空状态 |
| 旧存档不崩 | `Store.def()` 加字段 + `load()` 用 `asArr` 归一 |

## 2. 数据结构

```js
Store.d.translationHistory = [
  {
    id: 'tr::<taskId>::<时间戳>::<随机>', // 一次编辑会话的稳定 id
    at: '2026-10-23T11:20:31.000Z',       // ISO 时间（最后一次编辑）
    taskId: 'kaoyan-2023-english-1-tr',   // 题目 id（找不到题时只回填文本）
    taskTitle: '中国传统赠礼（汉译英）',   // 题目名称（截 60 字）
    mode: 'exam',                         // translation: exam | sentence | custom
    dir: 'en2cn',                         // auto 判定后的方向：en2cn | cn2en
    text: '……用户输入的完整译文……',
    chars: 126,                           // 去掉空白后的字符数
  },
  // 最多 5 条，最新在前
];
```

`Store.d.writingHistory` 同结构，只把 `mode` 换成写作页的 `tab`（`task | sentence | translation | ai`），
同时保留一个同值的 `mode` 字段，弹窗统一按 `entry.tab || entry.mode` 展示。

## 3. Store API

```js
Store.rememberInput(kind, entry) // kind: 'translation' | 'writing'
Store.recentInputs(kind)         // 最新在前，最多 5 条（返回副本）
Store.clearInputs(kind)          // 清空一类，返回清掉数量
```

- **去重**：同 `id` 视为同一次编辑会话 —— 更新内容/时间并移到最前，不新增条目；
- **上限**：写入后 `slice(0, 5)`，Store 层与视图层双保险；
- **空文本**：`text.trim()` 为空时不记录，避免「清空输入框」占掉一条记录；
- **坏条目**：`recentInputs` 过滤掉非对象/无 `text` 的旧数据，渲染不会崩；
- **副本**：`recentInputs` 返回浅拷贝，视图改动返回对象不会污染 localStorage 数据；
- **持久化**：每次写入立刻 `flush()`。

`Store.def()` 新增两个数组字段；`Store.load()` 像 `writeLog` 一样用 `asArr()` 归一
（字符串/对象/数字 → `[]`），旧存档与导入的残缺存档都能安全启动。

## 4. 触发点（何时落盘）

### 翻译页（js/views/translation.js）

| 场景 | 处理 |
|---|---|
| 编辑器 `#trAns` 输入 | `ta.oninput` → `_memoSoon(ta.value)`（App.debounce 800ms） |
| 提交评分（`_grade`，含计时到点自动提交） | 先 `_memoFlush()`，再 `_resetMemo()`（提交后输入算新条） |
| 换一题（`_next`） | flush + reset |
| 切题型 tab（真题/单句/自定义） | flush + reset |
| 筛选器换题、自定义题目下拉换题 | flush + reset |
| 单句「切方向」会清空作答 | 清空前 flush + reset |
| 清空按钮 / 新建自定义题 / 删除自定义题 | flush + reset |
| 返回按钮、侧栏/底部导航（`hashchange`）、关闭/切后台（`beforeunload`/`pagehide`） | flush（保留会话 id，下次回来继续编辑仍更新同一条） |

### 写作页（js/views/writing.js）

| 场景 | 处理 |
|---|---|
| 编辑器 `#editor` 输入 | `ed.oninput` → 立即同步 `this.essay`（词数仍 250ms 防抖刷新）→ `_memoSoon` |
| 提交评分（`_grade`） | flush + reset；手写识别/图片合并进来的文字先 `_memoSoon` 再 flush |
| 保存草稿（`save`） | flush（保留同一条记录，继续写会更新它） |
| 换一题（`nextTask`）、切 tab、切筛选、删除本题、自定义题目、AI 出题 | flush + reset（`_resetTaskState` 统一兜底） |
| 清空按钮 | 清空之前 flush + reset |
| 格式按钮 / 手写转文字（程序改 `value` 不触发 oninput） | 手动 `_memoSoon` |
| 返回、应用内换页、关闭/切后台 | flush |

> 防抖实现：`_memoSoon` 每次输入保存一份**快照**（含当次 tab/taskId/标题/方向），
> 800ms 后写 Store；`_memoFlush` 取快照立即写。换题/提交时 `_memoSess++`，
> 旧定时器即使晚到，也会因为 `sess` 不匹配而丢弃旧文本，不会把上一题写到新题名下。

## 5. 编辑会话 id 与「最多 5 条」如何保证

1. 视图在本次编辑会话第一次输入时生成稳定 id：`tr::<taskId>::<时间戳>::<随机>` /
   `wr::<taskId>::<时间戳>::<随机>`；
2. 同一题目连续输入复用该 id → Store 按 id 去重，历史里只占 1 条；
3. 换题/提交/清空时更新 session，下一次输入生成新 id → 新的一条记录；
4. Store 写入后 `list.slice(0, 5)`，第 6 条起挤掉最旧的；
5. 恢复记录后复用原记录的 id，继续编辑会更新这条而不是再堆一条。

## 6. 恢复规则

- 恢复入口：列表每行的「恢复」按钮（`data-memo="<下标>"`）；
- 翻译页：在记录对应的 `mode` 题池里按 `taskId` 找题；找到 → 切题型、方向、题目
  （筛选条件归零，避免目标题被旧筛选筛掉），文本回填 `this.answer`，清空旧评分/图片，
  重渲染 `_shell(App.freshView())`；**不自动提交**；
- 写作页：按记录里的 `tab` 找题（单句池 / 真题池 / 考研翻译池 / 当前 AI 题）；找到 →
  切 tab（单句 tab 同时恢复 `trDir`）并回填 `this.essay`，清空旧评分，重渲染
  `_shell($('#view'))`；**不自动提交**；
- 找不到题目（题目被删/换题库）→ 只回填文本，toast 提示「没找到对应题目」，
  **不切题型/tab/题目**；
- 恢复后 `_memo.id` 复用记录 id，`_memoPending` 清空，避免重复记录。
