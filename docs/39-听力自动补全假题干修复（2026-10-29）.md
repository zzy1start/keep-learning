# 39 · 听力自动补全：假题干 + 原文缺失修复（2026-10-29）

> 用户原话：**「自动联网补充全文后题干报错，听力原文没有，解决这个问题」**（附平板截图：Q1、Q2 的题干都是同一句 `*M*:Thatsoundsamazing.Doyouhavetorelocate?`，原文卡片仍显示「本篇没有听力原文」，顶部却绿条写着「题干已齐全，来源：原文口播」。）

## 1. 现象与复现（修复前真实复现）

| 观察 | 证据 |
| --- | --- |
| 题干是一整行原文对白，且两题一模一样 | 用户截图 Q1/Q2 都是 `*M*:Thatsoundsamazing.Doyouhavetorelocate?` |
| 原文并没有补进来 | 同一页原文卡片仍是「⚠ 本篇没有听力原文」 |
| 页面声称来源是「原文口播」 | 绿条「题干已齐全，来源：原文口播」 |

合成页面复现（按实站「每个单词一个 `<span>` + 说话人徽标 `<b>*M*:</b>`」的结构构造，Node 直接跑 `ListeningAutoFill.run`）：

```
修复前：
  stemsFilled = 1, stemsFrom = 'transcript', script = 0
  q[0] = '*M*:Thatsoundsamazing.Doyouhavetorelocate?'
  （候选正文同一行出现两次时，q[0]、q[1] 会被写成同一句）
```

## 2. 根因（四处叠加）

1. **联网正文抽取把英文粘成一个词**：`js/web-search.js` 的 `extractArticleText` 删行内标签时没有补分隔符，
   实站把每个单词包在 `<span>` 里，于是正文变成 `Thatsoundsamazing.Doyouhavetorelocate?`。
   AI 切出的原文/证据句带正常空格，逐字比对必然失败 → 原文被整段丢弃（「听力原文没有」的直接原因之一）。
2. **未核验的正文被当成「原文口播」抽题干**：`run` 第 2 步失败后 `aiSourceText` 仍留着候选页，
   第 3 步 `stemSource = aiSourceText || scriptText` 照用，把对白抽成「题干」写进卷子与补丁；
   而 `stripSpeaker` 不认 `*M*:` 徽标，「M」又被算成一个英文单词，两道门槛全部通过。
3. **没有去重、没有单句校验**：同一行对白在正文里出现两遍或用户点两次重试时，同一句会被分别写给 Q1、Q2；
   页面文案还统一写「补入的题干经同套听力逐字核对」，实际来源是原文/联网时根本没做过同套核对。
4. **搜索引擎召回不到已知原文页**（第二轮发现）：懒笔记的 2025-06 第 1 套原文页仍然在线且完整，
   但 Bing/百度/搜狗/360 当期分别被广告页、无关 docx、登录墙占位，纯搜索导致「原文补不进来」。

## 3. 修复内容

### 3.1 `js/web-search.js`：行内标签当分隔符

- `ANY_TAG_RE` 由删除改为替换成空格，并收紧标点前空白（`"amazing ."` → `"amazing."`）；
- 效果：`<span>That</span><span>sounds</span>` → `That sounds`；说话人徽标 `*M*:` 后也有空格。
- 回归断言：逐词 span 不得粘连、徽标后必须有空格。

### 3.2 `js/listening-autofill.js`：题干来源与可信校验（防编造硬约束加强）

| 改动 | 作用 |
| --- | --- |
| `run` 新增 `verifiedSource`，只在「结构化门槛 + AI 逐字证据 + 切分 ≥60% 逐字命中」全过后才赋值；第 3 步 `stemSource = verifiedSource || scriptText` | 未核验的候选正文**一律不抽题干**，从源头消灭「没原文却有原文口播题干」 |
| `SPEAKER_PREFIX_RE` 兼容 `*M*: / [W]: / (M):`；新增 `LEAKED_SPEAKER_RE` | 说话人徽标不再被当成英文单词混过题干门槛 |
| 新增 `looksLikeDialogue`，`stemLooksReal` 拒绝行首说话人标记与多句对白 | 一整行对白（哪怕以 `?` 结尾）不再能当题干 |
| 新增 `STEM_LEAD_RE`：顺序兜底、裸题号两个分支只认 What/Why/How/Where/When/Who/Which/According to 开头的单句；带 `Question 5` 明确标签的仍照旧 | 原文页的「5.」后面跟对白也不会被误当题干 |
| 抽取时按 `matchKey` 去重（含卷面已有题干） | 同一句原文只占一道题，Q1/Q2 不再复制同一句 |
| 新增导出 `sanitizeStems(papers, patches)` | 清掉旧版已经写进 `q.q` / `lsnPatch` 的假题干（行首说话人标记或一行两个问句），并删除失效的 `stemSource/stemFromSet`；真实题干不动（内置 41 道真题干扫描 0 误伤） |

### 3.3 `js/views/listening.js`：旧数据清洗 + 文案按来源说明

- `_shell`：`_applyPatches(pool)` 之后、`Picker.filter` 之前调用 `_sanitizeStems(pool)`，清完 `Store.flush()`；
  清掉的题按「缺题干」重新渲染，并会重新触发一次（已修复的）自动补全。
- 新增 `_stemVerifyNote(src)`，题干来源说明按 set / transcript / ai / web 分别陈述真实核对过程；
  不再一律写「补入的题干经同套听力逐字核对」。

### 3.4 `js/web-search.js` + `js/listening-autofill.js`：直连原文源（第二轮）

- 新增 `transcriptPageUrls(meta)`：按「年-月-套号」生成懒笔记原文页地址
  `https://english-exam.lazynote.cn/{cet4|cet6}/sections/listening/{YYYY}-{MM}-{setNo}/`；
  没有识别出套号时依次试 1~3 套。
- 新增 `collectDirectTranscript(meta, opts)`：直连抓取 + 正文抽取，返回和 `collectTranscriptText` 相同的
  `{text,sources,blocks,errors,tried}` 结构；404/超时只记 errors、不抛异常。
- `run` 第 2 步改为 **2a 先直连原文站**（必须过 `verifyTranscriptMatch` 结构化门槛），
  直连没拿到可用正文才 **2b 回退搜索引擎**多引擎抓取；两条路后面共用同一套 AI 逐字核验。

### 3.5 其它

- `sw.js` CACHE v21 → v22（脚本变了，PWA 用户刷新一次即拿到新文件）。
- `work/listening-autofill-contract.md` 增补 §5.4 修订记录。
