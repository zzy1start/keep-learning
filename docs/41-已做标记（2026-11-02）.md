# 41 · 已做过标记（听力 / 阅读 / 写作 / 翻译，2026-11-02）

> 用户原话：**「对已经做过的题添加已做过的标识，比如变暗或者在套卷后面标识已做过的选项；先给出几个解决思路和样板，再进行代码的修改，无线调试我已打开。」**

## 1. 验收口径（先写清楚，避免"做过"理解不一致）

- **算"做过"**：在听力/阅读里点过「提交作答」（写入 `Store.d.listenLog / readLog`）；
  写作/翻译点过提交批改、写入了 `Store.d.writeLog` 记录。
- **不算**：只点「显示答案」、只保存写作草稿、只输入未提交。
- 已做**不锁**：仍可点开重做；重新提交覆盖上一次成绩。
- 标识必须**不打断做题**：只在选择器 / 篇目快捷标签 / 页头出现，不改答题区。

## 2. 三个方案与样板

样板页（可直接在浏览器打开）：[`docs/samples/done-marker.html`](samples/done-marker.html)
平板实拍样板：`debug/ui-test/mockup1.png`、`debug/ui-test/mockup2.png`（debug/ 不进库）。

| 方案 | 做法 | 结论 |
|---|---|---|
| A · 变暗 + 勾 | 已做篇目整块降透明度，行尾 `✓已做 85%`；选中项保持高亮 | 最轻，已并入 |
| B · 套卷进度 + 分数 | 「月份 / 套别」选项后追加 `· 已做 1/7 篇`；「篇目」选项后追加 `· ✓已做 85%`；选择器头部追加 `已做 5 / 44` | 推荐，已并入 |
| C · 总进度 + 只看未做 | 再增加一个「只看未做」开关，隐藏已做候选 | **本轮未做**，留作第二轮 |

C 没做不是漏掉：它要改筛选/计数/空结果回退三处逻辑，单独做更稳。

## 3. 实际改动

### 3.1 新增 `js/done.js`（只读汇总，零数据迁移）
- `DoneBook.of(kind, item)`：听力/阅读读 `listenLog/readLog`；写作/翻译读 `writeLog`。
- 共用听力副本 id 形如 `xxx-shared-2`：查不到时回退到 `xxx`，避免"第 1 套做过、第 2 套共用却显示未做"。
- 写作/翻译旧记录没有 `taskId`：只按「标题 / prompt 完全相等或前缀相等」保守匹配，不做 includes，避免误标。
- 只保存草稿（`score/max` 都为空）不算做过。
- `label()` → `✓已做 85%` / `✓已做`（0 分只显示字，不显示 0%）；`detail()` → `上次 8.5 / 10 分（85%）`。

### 3.2 `js/picker.js`（听力/阅读/写作/翻译共用）
- `Picker.html({ statusOf })`：
  - 篇目 option 追加 `· ✓已做 85%`；
  - 场次/套别 option 追加 `· 已做 x/y 篇`（全做完 → `· ✓全部已做`；单题 → `· ✓已做`）；
  - 头部追加 `已做 x / y` 徽章；提示行加图例。
- `Picker.bind(..., { statusOf })`：换年份/场次后动态重填下拉时**同样保留**标记（否则一换筛选就全没了）。

### 3.3 各视图
- `js/views/listening.js`：
  - 篇目快捷标签 `.is-done`（变暗）+ 行尾 `✓已做`；页头 `✓ 已做过 85%`；
  - 提交后**原地刷新**标签 / 篇目下拉 / 页头徽章，不整页重建（不打断正在看的解析）；
  - 徽章只在**第一次**做该篇时 +1，重做同一篇不加。
- `js/views/reading.js`：选择器 statusOf + 页头 `✓ 本篇已做过 · 67%`。
- `js/views/writing.js`：选择器 statusOf；`writeLog` 新记录写入 `taskId`（旧记录仍按文本兜底）。
- `js/views/translation.js`：同上，`kind:'translation'` 记录写 `taskId`。
- `index.html`：`store.js` 之后加载 `js/done.js`。
- `css/modules.css`：`.part-tab.is-done`（opacity .58，选中 .94）、`.done-flag`、`.done-legend`。

## 5. 未做 / 后续
- 「只看未做」开关（方案 C）：需要同时处理筛选、当前计数、空结果自动回退，建议单独一轮。
- 写作/翻译历史记录的文本匹配是保守启发式；新记录已带 `taskId`，以后会越来越准。
- 若想给"套卷"加「全部做完」的整卷状态色（如金色边框），在 `setMark()` 上扩展即可。
