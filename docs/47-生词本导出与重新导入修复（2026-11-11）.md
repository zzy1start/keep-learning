## 1. 生词本导出 PDF（js/pdf.js，仅影响导出渲染）

用户截图里的问题与修复：

| 反馈 | 根因 | 修复 |

## 2. 重新导入提示「已导入，已跳过」（js/importer.js）

### 根因（两层，都命中了）

1. **文件指纹登记只增不减**：_dupLookup() 先查 Store.d.importedPapers 里的 sha256；导入成功就登记，删除篇目时没有清登记 → 同一个 PDF 再导入直接被挡住。
2. **按年/场/套的内容查重**：登记没挡住时，还会扫描三个模块里 mine 的篇目，只要同一年/场次/套别还有任何一篇就判重复。用户只删掉了坏的段落匹配，同套的传统阅读/选词填空还在 → 仍然「已导入」。

### 修复

1. 导入弹窗新增开关「**重新导入并覆盖**」（js/importer.js:1424）。勾选后：
   - _dupLookup(key, meta, ignoreContent)（js/importer.js:1225）直接返回 null，不再被文件指纹/同套内容挡住；
   - _clearPaperRegistry()（1290）清掉这套卷的查重登记；
   - 三个模块的入库都走 _putImported()（1333）**原地替换**同套同类旧篇目：沿用旧 id、旧篇号（readLog / 已做标记 / 划线都保留），新篇目才追加。段落匹配按 readingType 唯一匹配；传统阅读按 examPart/title、再按篇号；听力/写作按题型 + examPart/title。
2. **落盘也必须是替换而不是跳过**：_persist()（2611）原来「id 已存在就过滤掉」，覆盖重导沿用旧 id 时新内容根本写不回磁盘，重启又回旧分段。现在同 id 原地替换写回（contentBackup 分支同样处理）。
3. 删除篇目时如果这套卷已经没有任何导入篇目，forgetImportedPaper()（1267）会把查重登记一起清掉（阅读/写作删除入口都已接线）。

### 你的操作步骤

1. 刷新页面（PWA 缓存已升到 v28）。
2. 阅读页 →「导入真题」/「导入完整试卷」→ **勾选「重新导入并覆盖」** → 选同一个 PDF（单文件或整个文件夹）。
3. 导入后段落匹配按原卷 A–M 重新分段；同套其它篇目沿用旧 id，之前做过的进度不会丢。已被删除的段落匹配会作为新篇目重新入库（它本来就被删了，进度为空是正常的）。

## 5. 限制

1. 原型/词性/音标都由本地词典驱动：词典本身指错（如 used→us）或没有音标时，导出层不会凭空编造。
2. 导出只改呈现，生词本页面/存储里的词条仍是划词原形；若希望生词本列表也统一显示原型，需要再改添加/迁移逻辑（本轮未做）。
3. 「重新导入并覆盖」会覆盖同一年/场次/套别的**同套内容**；不同套、内置题不受影响。删除过的篇目重新导入后进度为空是预期行为。
4. 本轮没有做真实浏览器视觉复验（沙箱禁浏览器命名管道）；导出/入库均为 HTML/VM 级自检 + 源码契约验证，建议刷新后实际导出一份 PDF 看看。
5. 未重建 APK、未升版本号；下次构建 APK 时随 Web 资源一起打包。
