## 3. 数据迁移验证（导出 → 卸载/重装 → 导入）

### 3.1 原计划与实际限制

原计划用浏览器自动化真的点一遍「导出备份 → 卸载 → 重装 → 导入备份」。本环境行不通：

| 方案 | 结果 |
|---|---|
| `bsk`（浏览器扩展自动化） | 守护进程无法启动/连接：Job Object 禁止 breakaway、命名管道被沙箱拒绝（os error 5） |
| Edge `--headless=new` + CDP | 启动即失败：crashpad 写 `%LOCALAPPDATA%\Microsoft\Edge\User Data` 被拒、进程单例锁无法创建 |

所以没有在真实浏览器里点按钮，改为**直接驱动仓库里同一份 `js/store.js`** 做等价验证。

### 3.2 验证方法

用 Node `vm` 加载 `js/store.js`，把 `localStorage`、`window`、`App` 换成内存替身，跑三条真实代码路径：

1. **全量备份**：`Store.backup()` → 新上下文按「导入备份」的同一段代码恢复
   （`Store.d = Object.assign(Store.def(), j); Store.d.settings = Object.assign(Store.def().settings, j.settings); Store.flush()`）；
2. **空机器基线**：新上下文未导入时应为默认值；
3. **仅导入进度**：`Store.importProgress()` 应只覆盖 `PROGRESS_FIELDS`，保留本机 settings。

测试数据：1 个 SRS 词（cet6/abandon）、1 条生词本、1 次学习活动、`dailyNew=33`、`theme=dark`、`activeBook=cet4`。

### 3.3 结果

| 检查 | 结果 |
|---|---|
| 全量备份 round-trip（7 个字段逐一相等） | **PASS** |
| 空 profile 起步为默认值 | **PASS** |
| 仅导入进度：进度恢复、本机 `dailyNew=11` / `theme=auto` 保留 | **PASS** |
| 备份体积 | 2,102 B（全量）/ 1,264 B（仅进度） |

### 3.4 结论与边界

- **导出/导入代码本身正确**：全量备份能 1:1 还原，进度导入不会覆盖本机 AI Key / 外观设置。
- **卸载不会删学习数据**：数据在浏览器（域名 `127.0.0.1:8777` 的 localStorage），安装器只写
  `%LOCALAPPDATA%\KeepLearning` + 快捷方式 + HKCU 卸载项，卸载只删这些。
- **未验证**：真实浏览器里的点击流程、真实 localStorage 的持久化、含个人题库的大备份导入。
  这三项需要在一台正常机器上手动走一遍（见下）。

### 3.5 手动复测步骤（约 2 分钟）

1. 打开应用 → 设置 → 数据管理 → **导出备份**，记住 json 位置；
2. 控制面板卸载 Keep Learning → 重新安装 → 打开应用：**学习数据应仍在**（卸载不碰浏览器数据）；
3. 换一个浏览器（或另一台电脑）打开 → **导入备份** → 选中刚才的 json → 检查单词进度/生词本/统计是否一致；
4. 可选：只导出「学习进度」，在新机器上「仅导入学习进度」，确认 AI Key 与主题没被覆盖。
