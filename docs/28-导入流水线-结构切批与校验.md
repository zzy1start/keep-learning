# 28 · 导入流水线：结构切批 + 原文位置 + 程序校验（2026-10-17）

> 背景：AI 导入真题原来只有「固定 4500 字切段 + 紧凑 prompt + 递归二分」，
> 截断能缓解，但错分、漏题、耗时长仍在。按用户方案重构为：
> **AI 负责识别结构、处理模糊处；程序负责保留原文、校验完整性、合并结果。**

## 1. 目标与现状差距

| 目标 | 改造前 | 改造后 |
|---|---|---|
| 原文位置/页码 | `readPdfText` 直接 join，页码丢失；AI 结果无位置字段 | PDF 每页保留 `{no,start,end}`；批次带 `[start,end)` 与 `pageStart/pageEnd` |
| 结构优先切段 | 固定 4500 字切段，可能把文章和题目拆开 | 先按 Section/Passage/Text/Questions N to M/Directions 切结构块；同模块合并；超长才按段落/题号/句子边界拆（`continuation` 标记） |
| 每批同类结构 | 一次请求同时产出听力/阅读/写作三模块 | 每批只输出本批所属模块；模块归属从 Part 大标题向下继承 |
| 完整性依据 | 只看 AI 的 `complete:true` | 程序校验：题号集合对照原文、选项数量、答案下标/词库/段落字母、题干与选项能否在原文定位 |
| 失败处理 | 整段二分重试（最多 3 层） | 只重试校验失败的那一批，并把结构化错误清单回传给 AI；修不好进失败清单，不整卷重解析 |
| 缓存/续跑 | 无 | 成功批次按 `原文+模块+考试类型+prompt版本` 哈希缓存到 localStorage，重跑同一份文件直接命中 |
| 考试类型核验 | 有 confidence/evidence，但 evidence 未核对 | evidence 必须在正文里能找到（逐字或 ≥8 字连续片段），否则 type 置空、转人工确认 |

## 2. 新流程

```
提取文本（PDF 保留页区间）
  → TextRepair 修复（若文本长度变化则丢弃页码区间，避免位置错位）
  → 考试类型核验（证据必须能在正文定位）
  → ImportPipeline.buildBatches：按结构切批（每批同模块，带位置）
  → 每批单独调用 AI：只输出本批模块 + 逐字复制原文 + 保留原题号
  → ImportPipeline.validateBatch：程序校验（errors / warnings / stats）
  ├─ 通过 → 写入 localStorage 批次缓存
  └─ 失败 → 带错误清单只重试该批；仍失败记入 failures
  → 按原文顺序合并模块（_finalizeModules：考研翻译归位、写作原题逐字回填、阅读碎片合并）
  → _commitOutput 分模块入库；成功弹窗展示批次数/缓存命中/题号覆盖/失败批次
```

兜底：若结构切批不足 2 批或任一步抛错，`_aiSplit` 自动回退到旧的整卷切分
（`_aiSplitLegacy`，保留原有并发/紧凑 prompt/二分递归），保证不因新路径失败而无法导入。

## 3. 模块 API（`js/import-pipeline.js`，纯逻辑无 DOM）

| 函数 | 说明 |
|---|---|
| `buildBatches(text, {pages?, maxChars?})` | 结构切批，返回 `{id,index,title,module,start,end,pageStart,pageEnd,text,continuation}` |
| `expectedNumbers(text)` | 从 `Questions N to M` / 编号行推导期望题号（兼容 `5 1.` OCR 拆分） |
| `validateBatch(result, batch, {module?})` | 返回 `{ok,module,items,errors,warnings,stats}` |
| `hashText(text)` / `batchKey(batch,meta,promptVersion)` | 稳定 FNV-1a 哈希，用于批次缓存 key |
| `containsSource(source,piece)` | 压缩空白标点后判断原文是否包含某片段（覆盖校验用） |

错误码：`NO_ITEMS / EMPTY_ITEM / EMPTY_TITLE / NO_QUESTIONS / MISSING_QUESTIONS /
EXTRA_QUESTIONS / DUP_QUESTION_NUMBER / OPTIONS_NOT_4 / EMPTY_OPTION / ANSWER_INDEX_INVALID /
ANSWER_OUT_OF_BANK / ANSWER_OUT_OF_PARAGRAPHS / NO_WORD_BANK / NO_TRANSLATION_TEXT /
EMPTY_PROMPT / SOURCE_RANGE_OUT_OF_BATCH`；
警告：`DUP_TITLE / STEM_NOT_IN_SOURCE / OPTION_NOT_IN_SOURCE`（AI 改写时只提示，不判失败）。

## 4. importer 接线（`js/importer.js`）

- `_extract` 统一返回 `{text, pages}`；PDF 由 `readPdfText` 计算页区间（`pages:[{no,start,end}]`）；
  `_parseAndSave` 里 TextRepair 改动文本长度时 `sourcePages=null`。
- `_aiSplit` → `_aiSplitBatched`（新）/ `_aiSplitLegacy`（兜底）。
- `_aiSplitBatched`：并发 3 批；每批 `_batchPrompt`（单模块 + 原文逐字 + 错误清单定向修复）；
  `validateBatch` 校验；成功写 `_batchCacheSet`；失败进 `failures`。
- 缓存：`localStorage['keeplrn_import_cache_v1']`，最多 40 批 / 约 800KB，超限丢最旧；
  配额不足或隐私模式静默失败。
- 成功弹窗新增：批次数、缓存命中、题号覆盖、选项原文覆盖率、失败批次及错误码。

## 6. 失败兜底（本地规则回填，2026-10-17 追加）

AI 两次都没通过校验时，不再直接判整批失败，而是先做**本地规则回填**（`repairFromSource`）：
- 缺选项：按题号从原文找回 A-D 选项补齐；缺题（仅阅读、非 Section A/B）：从原文题号行生成题目，答案 `a=null`；
- 回填后重新校验：通过则写缓存并继续，统计里记录 `repairs / repairedBatches`；仍不通过才进入失败清单；
- 听力缺原文脚本无法本地补 → 仍会失败并列出，不伪造内容。

## 7. 二次兜底：批内二分 + 警告核对（2026-10-17 追加）

- **批内二分**：本地回填仍不通过、且该批还很长（>900 字符）时，用 `splitTextHalves/splitBatch`
  在段落/题号/句子边界一分为二，各自再走一遍「重试 → 本地回填」（只拆 1 层，避免请求爆炸）；
  父批重新校验通过就丢弃子批失败记录，否则保留更精确的子批错误。子批校验用 `partial` 模式：
  只查结构（选项数/答案/重复/位置），题号覆盖由父批统一校验（二分可能把 "Questions N to M"
  头和题目拆到两半）。
- **warnings 核对列表**：成功弹窗把 `STEM_NOT_IN_SOURCE / OPTION_NOT_IN_SOURCE` 等警告
  收进可点开的 `<details>` 列表（标题 · 错误码 · 详情），不再只显示一个数字。

## 8. 录制 AI 输出重放度量（2026-10-17 追加）

`tools/import-replay/*.json` 保存按批次固定的 AI 输出（含"首轮故意失败 → 重试修好"），
`tools/check-import-replay.cjs` 重放并统计「完整率 / 错分（金标题号→模块映射）/ 重复 / 耗时 / 重试」：

| 录制 | 批次 | AI 调用 | 重试批 | 完整率 | 缺题/重复/多出 | 错分 | 串行耗时 | 并发1/2/3/4 墙钟 |
|---|---|---|---|---|---|---|---|---|
| cet4 | 1 | 2 | 1 | 100% | 0/0/0 | 0 | 3.9s | 3.9/3.9/3.9/3.9s |
| cet6 | 4 | 5 | 1 | 100% | 0/0/0 | 0 | 8.7s | 8.7/6.3/5.7/4.5s |
| kaoyan | 2 | 3 | 1 | 100% | 0/0/0 | 0 | 4.7s | 4.7/2.7/2.7/2.7s |

- 「错分」用 fixture 里的金标 `expected`（题号 → 模块）逐题核对，三份录制均为 0；
- 二次导入全部命中批次缓存（0 次 AI 请求）；
- **并发决策**：录制数据显示 3 并发已比串行/2 并发明显快；4 并发在 4 批样本上更快（5.7s→4.5s），
  但小样卷收益小、且官方接口限流未知，暂保持 `CONC=3` 作为稳定性与速度的折中，后续用真实录制复核。
