# 第二十轮：翻译判分重构 + 排版对齐写作页

需求：①在 GitHub 上找开源且好用的英语翻译项目，下载并据此优化翻译逻辑；②翻译界面排版与写作页保持一致。

## 1. 开源项目调研（数据取自 GitHub API，本机实测）

| 项目 | ★ | 许可证 | 语言 | 结论 |
|---|---|---|---|---|
| [mjpost/sacrebleu](https://github.com/mjpost/sacrebleu) | 1261 | Apache-2.0 | Python | **采用**：chrF/chrF++ 参考度量移植进前端 |
| [Unbabel/COMET](https://github.com/Unbabel/COMET) | 781 | Apache-2.0 | Python | 神经度量，需模型权重与算力，纯静态站点无法运行 |
| [MicrosoftTranslator/GEMBA](https://github.com/MicrosoftTranslator/GEMBA) | 156 | CC-BY-SA-4.0 | Python | 借鉴其 MQM 错误类型学**思路**；其提示词文本为 CC-BY-SA，不直接复制 |
| [argosopentech/argos-translate](https://github.com/argosopentech/argos-translate) | 6550 | MIT | Python | 离线 NMT，但依赖 Python 与模型包，静态站点不可用 |
| [LibreTranslate](https://github.com/LibreTranslate/LibreTranslate) | 17033 | AGPL-3.0 | Python | 需自建服务；AGPL 有传染性，不引入 |
| [nidhaloff/deep-translator](https://github.com/nidhaloff/deep-translator) | 2046 | Apache-2.0 | Python | 在线翻译 API 的封装，与「完全本地」目标冲突 |
| [harisnae/multilingual-translator-offline](https://github.com/harisnae/multilingual-translator-offline) | 15 | Apache-2.0 | JavaScript | transformers.js + OPUS-MT ONNX 浏览器离线翻译；首次需下载 40–80MB 模型，**列为可选后续** |
| [huggingface/transformers.js](https://github.com/huggingface/transformers.js) | 16342 | Apache-2.0 | JavaScript | 上一条的基础库，本次未引入 |

**取舍**：本项目是**离线静态站点**（无构建、无 Python、无后端）。能直接落地且收益最大的是
sacrebleu 的 **chrF**——纯字符串统计，几十行即可移植，正好补上此前「评分只由模型说了算」的空白。
神经度量与离线 NMT 都要求模型权重（几十 MB 起），会破坏「打开即用、完全本地」的产品前提，
因此**只把 chrF 移植进来**，把 ONNX 离线翻译留在后续（需要用户明确接受体积代价）。

## 3. 翻译判分逻辑改造（`js/ai.js` + `js/translate-metric.js`）

1. **无 AI 也能评分**：未配置 AI（或调用失败）时，有参考译文的题目退回本地 chrF 评分，
   结果标记 `degraded` + `reason`，界面显示「本地规则模式」；没有参考译文时**如实拒绝，不猜分**
2. **完整性门槛**：按原句数 / 题号数对比译文句数，明显漏译时把总分上限压到覆盖率 × 满分
   （此前「只译一句也能拿高分」，写作侧早有 `capIncompleteEssayScore`，翻译侧一直是空白）
3. **chrF 对齐核查**：有参考译文时算 chrF，相似度 < 25 却给了 ≥ 60% 的分 → 压到满分一半并提示人工复核；
   相似度 ≥ 85 却给低分 → **只提示、不自动加分**（chrF 看不到语义错误，抬分风险更大）
4. **压分后四维等比缩放**（`scaleScore`）：保证每维 ≤ 满分/4、四维之和 = 总分，
   与 `translationScoreIssue` 的一致性校验、界面四维条都不打架
5. **提示词升级**：明确「只评原卷要求的编号句/划线部分」、要求逐句 `coverage` 核对、
   按 MQM 风格把问题归类到 准确性/流畅性/语法术语/用词升级，并要求每条建议引用学生原话片段
6. **满分不再写死 30**：按题目 → 考研英语一 10 / 英语二 15 → 单句 20 推导，页头可手填
7. **失败形状与 AI 侧统一**：本地评分的失败结果不带 `score`，避免「接口失败」被记成 0 分练习

## 4. 排版对齐写作页（`js/views/translation.js`）

| 位置 | 改造前 | 改造后（与写作页一致） |
|---|---|---|
| 页头 | 自定义 `ph-l` + 返回箭头 + 右侧 chip | `phead` + 返回按钮 + `phead-ic` 图标 + 中英标题 + 右侧满分输入与评分按钮 |
| 右栏 | 普通 div，不吸顶 | `an-panel`（吸附 + 内部滚动），AI 评分卡带 AI 状态标签 |
| 空状态 | 一行纯文字 | `_emptyGrade()`：图标 + 两行说明 |
| 输入区 | `inp` 文本框 + 底部一个按钮 | `editor-tool` 工具栏（清空 / 拍照上传 / 字数）+ `editor` 输入区 + 右对齐主按钮 |
| 参考译文 | 无复制按钮 | 卡片头「📋 复制」，与写作页同一个交互 |
| 卡片间距 | 依赖 CSS 默认 | 显式 `margin-top:14px`，两栏节奏与写作页一致 |
| 单句练习 | 直接给原文 | 增加方向提示 `tr-dir-tip` 与「参考答案（点击显示）」`tr-hidden` |
| 结果面板 | 只有分数与建议 | 追加「完整性检查」「chrF 对齐值」「逐句核对」三块，判分依据可见 |
