## 2. 来源数据从哪来（只改导出呈现，不改存档结构）

1. **新加的词**：阅读页 `_curPaper()`（js/views/reading.js）在加生词时把当前篇目的卷面快照写进 `item.paper = { id, year, session, setNo, level, mine }`。
   已接线 3 处入口：点击单词浮层「＋生词本」（阅读划词）、划线分析面板「＋生词本」（阅读划线/明日待背）、阅读页「导出阅读生词 PDF」的临时条目。
   阅读页那份导出混着「生词本里所有阅读来源的词」，所以只有本篇文章的划线词盖当前卷面，其余沿用各词自己加词时的 `paper`/`origin`，不把别的卷子算进当前套。
   走 `Store.nbAdd()` 原样合并字段，备份 v2 也会带上（体积可忽略）。
2. **老数据（用户现在这批 44 词只有 `srcTag` + 一句自由文本 `origin`）**：导出时按证据强弱回填（`_nbPaperOf`）：
   ① `origin` 里的**原句**只在某一篇出现过 → 认那一套（最硬）；
   ② `origin` 里的**文章标题**在全库只有一套卷子使用 → 认那一套（Passage One 这类重名标题会主动放弃）；
   ③ 兜底：这个词只出现在**一套自己导入的卷子**正文里 → 认那一套；内置教材篇目（`mine:false`）不参与。
   三步都对不上就只写「阅读划词」，宁可少写也不编年份。
3. 日期口径没变：仍按 `addedAt` 分日、倒序、每天独立成节、各自双栏。

## 5. 限制

1. 老词回填依赖 `origin` 文本或该词在自有卷子正文里唯一出现；极端情况（词在多套卷子正文里都出现、且没有原句/标题）会退化成「阅读划词」。
2. 多套混导只展示第一套做代表 + 「等 N 套试题」，不逐套罗列（顶部要简化）；需要完整套卷明细时看日标题或后续再做按套分组。
3. 来源粒度到「年·月·级别·套别 + 来源入口」，未细分到题型/篇目（如「仔细阅读 Passage One」）——本轮用户只要到套卷，若以后要更细可加在来源行尾部。
4. 内置阅读材料（非用户导入）也会按 `year/session/level` 显示，但不会出现在「等 N 套试题」的兜底归属里。
