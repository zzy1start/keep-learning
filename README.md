# Keep Learning · 本地英语学习工作台

一个**完全本地运行**的英语学习应用，包含单词、听力、阅读、写作、翻译五大模块。
所有学习数据只保存在你自己的浏览器里，不上传任何服务器。

> **开源仓库**：<https://github.com/zzy1start/keep-learning>

> 构建方式见 [BUILDING.md](BUILDING.md)。

## 快速开始

### 方式一：桌面快捷方式（推荐）

Windows 下可以先双击「创建桌面快捷方式.bat」生成这三个入口：

| 文件 | 作用 |
|---|---|
| **Keep Learning 英语学习.url** | 双击打开网页（服务器已在运行时最快） |
| **Keep Learning 启动.bat** | 双击启动完整流程：自动开服务器 + 开浏览器 |
| **Keep Learning 停止服务.url** | 双击停止本地服务 |

换电脑或桌面文件丢了？双击应用目录里的 **「创建桌面快捷方式.bat」** 即可重新生成。

### 方式二：命令行

```bash
node serve.js          # 默认 8777 端口
node serve.js 9000     # 指定端口
```

然后访问 <http://127.0.0.1:8777>

### 启动器做了什么

双击「启动.bat」时依次执行：

1. 检查 Node.js 是否安装（没装会提示下载地址）
2. 用 `tools/port-check.js` 探测 8777 端口
   - **已在运行** → 直接开浏览器，不重复启动
   - **空闲** → 后台启动服务器 → 等待就绪 → 开浏览器
3. 超时（25 秒）会提示可能原因并给出处理方法

关掉启动窗口**不会**停止服务（服务在后台独立运行）。
要停止，双击「停止服务」。

### 为什么需要本地服务器？

浏览器安全策略禁止 `file://` 协议页面 `fetch()` 本地 JSON 词库。
必须通过 `http://127.0.0.1` 访问才能加载词库。这不是上传，只是本机回环。
服务器默认监听 `0.0.0.0`（方便同 Wi-Fi 的平板/其他设备访问，只在局域网内可见；正式支持仅 Windows + Android 平板）；
只想本机用就加 `--local` 回到只监听 `127.0.0.1`。详见文末「多端使用」。

#### 跳过简单词（按掌握量自动跳级）

首次做词汇量测试后，系统按得分率判断哪些基础词你已掌握，直接标熟跳过：

| 测试正确率 | 跳过词数（六级为例） | 剩余需学 |
|---|---|---|
| ≥ 90% | 3108 词（55%） | 2543 词 |
| 75–90% | 2542 词（45%） | 3109 词 |
| 60–75% | 1977 词（35%） | 3674 词 |
| 45–60% | 1243 词（22%） | 4408 词 |
| 30–45% | 678 词（12%） | 4973 词 |
| < 30% | 不跳过，从头学 | 5651 词 |

**原理**：词库加载时已按词频降序排列，数组尾部即词频最低的基础词（常见词）。
得分越高说明基础越扎实，可跳过的低频词越多。

**跳过的词并非不管**：标记为 `skipped`，仍按遗忘曲线安排复习（首次 30 天后），
只是不占用每日新词名额。

**可撤销 / 可手调**：
- 测试结果页有「撤销」按钮，一键回滚本次批量标熟
- 词书页有「调整跳过范围」滑块，可精确指定跳过多少词（0 = 全部从头学）
- 跳过的词与实际学过的词在统计中分开显示

### 按年份与篇章选择

听力、阅读、写作均支持 **年份 → 场次 → 篇章/题号** 三级选择，与真实考卷定位习惯一致。

- 听力：2023 年 6 月卷 → 第1篇 / 第2篇
- 阅读：同上年份场次，第 1–4 篇
- 写作：同上年份场次，第 1/2 题

内置题库按真题结构组织（2023年6月/12月、2024年6月）：
听力 6 篇 / 阅读 5 篇 / 写作 6 题。

>内置的是仿真题（真题受版权保护不能内置）。要练真题请用下面的「导入真题」。

### 导入真题（自己导入 + AI 逐题切分）

听力/阅读/写作/翻译页面右上角都有 **「📄 导入真题」** 按钮。

**格式**：`.txt` `.docx` `.pdf`（纯文本型）`.json`，也可直接复制粘贴。

**三步**：① 选类型+年份+场次 → ② 读取文件或粘贴全文 → ③ 点「用 AI 切分并入库」

**AI 切分**：自动识别 Section/Passage 边界、题号、四个选项、答案行，
按真题结构生成「一篇材料 + N 道题」。答案行（`Answer: 1-B 2-C 3-B`）会自动识别回填。

**未启用 AI 时**用规则切分兜底：按题号与选项模式切分，同样识别 `Answer:` 答案表。

**导入的题目**出现在对应年份选择器里，标记「我导入的题目」，可随时删除。
只存本机，不上传（仅 AI 切分时把题目文本发给你配置的接口）。

> 扫描版（图片型）PDF 无法提取文本，需先OCR 或直接复制粘贴。

### 听力 LISTENING

- **发音引擎**：浏览器内置 Web Speech API，**离线可用**，不依赖任何在线 TTS
- **三种题型**：单句听力、对话听力、六级听力量题
- **改/写双模式**：
  - 「改」模式：显示原文，点击任意句子可单独复现；支持逐词高亮
  - 「写」模式：原文隐藏（打码+禁止选择），做听写练习，提交后给批改结果（还原率、漏写词、多写词）
- **播放控制**：全文播放、循环播放、逐句播放（当前句高亮）、变速0.6–1.15x
- **作答**：提交后给分+ 逐题解析

### 阅读 READING

**做题模式**
- 倒计时（10–40 分钟可选），到时自动提交
- **禁止查词**：单词不可点击，纯模拟真实考试
- 可调预计得分

**修改模式**
- 6 种划线工具（黄/蓝/绿/粉高亮、下划线、波浪线）
- **点词查词**：10.4 万词条词典，支持屈折还原（`challenges`→`challenge`）
- **划词分析**：拖选任意词或句子 → 自动识别（≥4 词判为长难句）
- **长难句分析**：句型结构、主谓宾成分标注、语法要点、整句翻译
- 加入生词本 / 明日待背 / AI 深度解析（词根、搭配、近反义、近年用法）
- 一键导出生词本 PDF（含日期、来源标签、来源分析）

### 写作 WRITING

- **四种练习**：真题写作、单句练习、AI 练习题、自定义题目
- **三种输入**：键盘、手机软键盘、**电子笔手写**（canvas 绘制，AI 视觉识别转文字）
- **四维评分**：内容完整性 / 逻辑结构 / 语言表达 / 词汇语法，各15 分
- **修改建议**分5 类：综合 / 结构 / 语言 / 词汇升级 / 句式
- **词汇升级对比**：`good/bad` → `beneficial/detrimental` 并解释原因
- 润色后范文 + 草稿保存 + 写作历史

### 翻译 TRANSLATION

- **三种练习**：真题翻译（导入的考研翻译题）、单句练习（内置考研单句，英译汉 / 汉译英可切换）、自定义题目
- **四维评分**：语义准确性 / 信息完整性 / 中文通顺度 / 术语与表达，各占本题满分四分之一
- **满分按题型推导**：考研英语一 10 分、英语二 15 分、单句 20 分，也可在页头手填（存本机）
- **两条不依赖模型的独立校验**（详见下方「第二十轮」）：
  - **完整性检查**：按原句数 / 题号数对比译文句数，漏译时压低总分上限（考研英语一 5 个编号句尤其明显）
  - **chrF 对齐核查**：与参考译文的字符 n-gram 重合度（移植自开源 sacrebleu），相似度极低却给高分时压制并提示人工复核
- **未配置 AI 也能练**：单句练习与带参考译文的自定义题用 chrF 给出本地评分（界面上标注「本地规则模式」）；
  没有参考译文的整篇翻译会如实说明无法评分，**不猜分**
- **拍照/上传**：手写译文照片交给 AI 识别后评分（需要 AI；未配置时明确提示不可用）
- 排版与写作页一致：页头（返回 + 图标 + 中英标题 + 满分与评分按钮）、工具栏输入区、右栏吸顶 AI 面板、参考译文复制按钮
### 其他

- **生词本**：按来源筛选、搜索、导入词表（txt/csv/JSON）、导出 PDF（含来源分析）
- **统计**：连续天数、近7/14 天、词书进度、写作记录、学习报告 PDF
- **设置**：AI 配置、主题、语速音色、手写笔色、启动弹窗开关、数据备份/恢复

### 4. 修复做题模式改时间的 bug

**原问题**：做题模式下改时间会强制跳到「修改模式」，而修改模式又显示同一个下拉框，形成看起来"不能改"的死锁。

**修复**：两种模式都可直接改时间，不再强制切换。修改模式下计时器标注「限时（不计时）」并禁用暂停按钮。

**顺带修掉两个更深的问题**：
- 用户设定的时间不保留：`_shell()` 里无条件用 `p.timeLimit * 60` 覆盖 → 改为 `this.timeLimit || p.timeLimit`，仅在切篇/切筛选时重置
- **每选一个选项倒计时归零**：选答案时调 `_shell()` 整页重绘，而 `_shell` 会重置 `left` → 改为局部更新选中态。新增「已答 N/共 M 题」计数（同一题重复点击可取消选择）

### 5. 树园关联听说读写 + 时长 + 正确率

树不再只跟背单词挂钩。当日**学习质量**由六项加权：

| 维度 | 权重 | 说明 |
|---|---|---|
| 单词 | 14% | 满 20 词记满分 |
| 听力 | 10% | 满 2 次 |
| 阅读 | 11% | 满 1 篇 |
| 写作 | 10% | 满 1 篇 |
| **时长** | 20% | 5 分钟起算，10–45 分钟最佳，过长视为低效 |
| **正确率** | 35% | 累计对/总，无数据按 0.7 计 |

**关键设计**：成长度 = `min(质量上限, 记忆保持率曲线)`，其中 `上限 = 0.55 + 0.45 × 质量`。
所以**只刷数量不练准确率，树就长不满**——质量和时长不是摆设，是真的影响成长。

每个树卡片显示 `Q{质量分}`，点开有完整质量构成条形图。

### 6. 铁树开花 🌸

取自成语「铁树开花」——比喻极难之事终于实现，用作学习表彰。

**长成**：连续学习满 **30 天** → 园中长出一棵铁树（永远长不大的那种）

**开花条件（需全部满足）**：

| 条件 | 阈值 |
|---|---|
| 连续学习 | ≥ 30 天 |
| 累计学习 | ≥ 60 天 |
| 平均记忆保持率 | ≥ 80% |
| 平均学习质量 | ≥ 70% |
| 掌握词数 | ≥ 500 词 |

达标后自动开花，显示粉色横幅 + 花朵动画，开花记录入库（日期/连续/累计/保持率/质量/词数）。
同一天不重复开花，之后达成更高连续天数时可再次开花。

点铁树卡可看每项条件的进度条和历史开花记录。

## 本轮新增（7 项）

### 1. 修复「AI 未启用」+ AI 结果就地展示

**问题**：填好 DeepSeek API 后，阅读页仍显示「未启用 AI」。

**根因**：`AI.ready` 要求 `enabled && key && baseUrl && model` 四项全满足，
但 `enabled` 来自一个独立开关——用户填完三项忘了拨开关，就一直显示未启用，界面却没有任何提示。

**修复**：
- 三项（Base URL / Key / 模型）**填齐即自动启用**，无需手动拨开关
- 设置页顶部加**状态指示灯**：「● 已启用」或「● 未启用　缺少：Key、模型名称」
- `baseUrl` 自动规范化：容忍用户误填 `/chat/completions` 后缀与尾部斜杠
- 新增 `AI.missing()` 返回缺失项名

**同时**：点「✨ AI 深度解析」不再跳转到「AI解析」tab，
而是在**当前面板顶部内联**显示结果（`.ai-inline`），带「✕」可隐藏。词性翻译和长难句分析都支持。
换词时自动清空上一个词的 AI 结果。

### 5. 听力逐词高亮连贯

**问题**：`Excuse me` 的第一个 `me` 念到时高亮，第二个 `me` 不亮。

**根因**：原实现**根本没有逐词高亮**——`play` 是整段 `Speech.speak()`，
没有 `onboundary` 回调。截图里"reading"的高亮其实是生词 `<b class="sp">` 的静态样式。

**修复**：新增 `_playWords()`，按句分组、句内**逐词朗读并高亮**，
每个词朗读时定位对应 span 加 `.on`。不用 `onboundary` 是因为部分浏览器/语音包不触发该事件
（会随机出现"念到某句就没高亮"）。

`_wSpan()` 把每句拆成带序号的 `<span class="w" data-wi="N">`，
**按出现位置编号**而非按词去重——所以同一句里重复的词是不同节点，能分别高亮。
实测「Excuse me, could you tell me...」中两个 `me` 编号独立。

### 6. 新增四级听力题

听力页新增「四级听力」tab：**5 篇短对话（男声为主）+ 2 篇短篇听力**，共 **19 道配套题**。

- 短篇：校园共享单车项目、失物招领处（带指示性开场与具体信息问答）
- 每题都有 `explain`（中文解析）与 `evidence`（原文依据）
- 全部符合四六级听力题型与难度

### 7. 写作：计时重构 + 总分 + 图片 + 双向翻译

**计时状态机**（原来点「开始批改」就直接跑了）：

### 6. 种树养成系统 🌳

首页「开始学习」右侧是**我的树园**。每天首次学习种下一棵树苗，树的长势完全由**遗忘曲线**决定。

#### 核心公式

```
保持率 R(t) = e^(−t / S)      S = ef × 间隔天数
t = 距上次复习的天数
```

这与 SM-2 间隔重复模型一致：**复习间隔越长，遗忘越快**；`ef` 随每次成功复习上升，所以掌握好的词掉得慢。

#### 状态判定（阈值固定）

| 条件 | 状态 | 说明 |
|---|---|---|
| R ≥ 85% | 🌳 成树 | 记忆牢固 |
| 55% ≤ R < 85% 且**未到期** | 🌱 成长中 | 还没到复习点，不算忘 |
| 55% ≤ R < 85% 且**已逾期** | 🍂 枯萎 | 暂时枯萎，**复习即恢复** |
| R < 55% | 🪵 木桩 | 永久枯萎，**永不恢复** |

**关键性质**：到期当天复习时 `t = 间隔`，此时 `R = e⁻¹ ≈ 37% < 55%`，
所以**「到期不复习必然开始枯萎」**——这正是艾宾浩斯遗忘曲线，没有绕过余地。
反过来，掌握牢固的词（`ef` 高→间隔长）即使过了很久 `R` 仍可能 >55%，不会平白枯萎。

#### 不可绕过

- 手动改数据库不会改变状态判定（`refresh()` 每次都从 SRS 记录重算）
- 木桩一旦生成，`refresh()` 直接 `continue` 跳过，**任何操作都不会让它复活**
- 实测：手动把木桩的 `R` 设成 0.999 再刷新 →仍是 `stump`

实测枯萎树复习后：保持率 70% → 100%，从 `withered` 变回 `long`。

#### 树种

内置 **22 种，辽宁地区常见 15 种**（约 70% 概率池），依据《沈阳市绿地树种名录》与辽宁数字植物标本馆：
油松、樟子松、落叶松、红皮云杉、白桦、蒙古栎、辽东栎、银杏、刺槐、小青杨、垂柳、水曲柳、元宝槭、国槐、榆等。

不同树种有不同形态（针叶塔形、圆冠、垂柳垂枝、白桦树干斑纹、竹节、花树…）。

**校树**：首页树园点「设置校树」填入本校校树，之后会以约 **40%** 概率出现。

|---|---|
| Base URL | `https://api.openai.com/v1`（OpenAI）<br>`https://api.deepseek.com/v1`（DeepSeek）<br>`https://api.moonshot.cn/v1`（Kimi）<br>`https://dashscope.aliyuncs.com/compatible-mode/v1`（通义）<br>`http://localhost:11434/v1`（本地 Ollama） |

#### 模型名一定要点「获取可用模型」

各家模型名变动很频繁，**手填极易踩坑**。例如：

- DeepSeek 在 **2026-07-24 下线了 `deepseek-chat` 和 `deepseek-reasoner`**，

- 填旧名字会报 `HTTP 400: The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed deepseek-chat`

点「获取可用模型」会向你的接口发`GET {baseUrl}/models`，
拿到该Key 真实可用的模型列表并自动填入，杜绝这类错误。
若某服务商没实现 `/models`，会明确提示"请手动填写模型名"。

#### 常见错误提示对照

应用会把接口原始报错翻译成可操作提示：

| 原始报错 | 含义与处理 |
|---|---|
| `HTTP 400 ... supported API model names are ...` | 模型名不对 → 点「获取可用模型」 |
| `HTTP 401 Authentication Fails` | Key 无效/未激活 → 检查 Key |
| `HTTP 429 insufficient balance` | 额度不足或限流 → 充值 |
| `HTTP 404` | Base URL 写错 → 通常应以 `/v1` 结尾 |
| `Failed to fetch` | 该服务不支持浏览器直连（CORS）→ 换服务商或用本地 Ollama |

> **安全说明**：Key 只保存在你自己浏览器的 localStorage，请求直接发往你填写的接口，
> 不经过任何第三方服务器。手写识别需要支持图片输入的模型（多模态），纯文本模型不影响其他功能。

## 常见问题

**Q：双击 index.html 打开是空白/词库加载失败？**
必须用 `serve.js` 或 `启动.bat` 访问 `http://127.0.0.1:8777`。`file://` 协议下浏览器禁止 fetch 本地 JSON。

**Q：听力没有声音 / 提示"缺少语音包"？**
先看「设置 → 🩺 发音环境诊断」里的英语音色数量：
- 0 个 = 系统没装英语 TTS。Windows 在「设置 → 时间和语言 → 语音」安装；Android 平板在系统 TTS 设置里安装 English 语音数据。网页/APK 不能替你下载系统音色。
- 有音色但没声 = 检查媒体音量/静音，以及是否先点过页面（浏览器/WebView 要求用户手势后才允许发声）。
- **iPad / iPhone、macOS、Android 手机在制作中，Linux 未支持；均暂不提供排查。**

**Q：手写识别无效？**
需要 AI 视觉模型（如 gpt-4o / qwen-vl-max）。且识别结果会与文字稿合并，不是实时 OCR。

**Q：localStorage 满了？**
写入时会提示。当前设计约 2KB/1000 次学习记录，正常使用几个月都不满。
仍可在设置页「导出备份」后清理。

**Q：换电脑怎么迁移？**
设置页 → 导出备份 → 得到 JSON 文件 → 新电脑导入备份。词库文件本身无需迁移。

| 证书 SHA-1 | `4D:C1:AA:F9:E0:54:CF:6B:A9:1A:3C:B9:95:98:01:33:70:DE:4D:F5` |

> ⚠️ 官方发布的 APK 均使用上述证书签名，签名方案 v1 + v2。
> **指纹不符的一律不是官方包**，即使包名同样是 `com.keeplrn.tablet`。
> 包名可以伪造，签名私钥不能。
>
> 🧪 GitHub Actions 自动构建的 APK 是 **debug 签名**（文件名含 `CI-debug`），仅供测试；
> 官方包以本节指纹为准，由维护者本地用正式 keystore 构建。

### 怎么自己校验

**电脑（需要 Android SDK build-tools）**

```bash
apksigner verify --print-certs 你的.apk
```

输出里的 `Signer #1 certificate SHA-256 digest` 应等于上面的 SHA-256
（注意 `apksigner` 输出为小写无冒号形式：
`44f02bf27f1b662e018631641c309cb0b86f1633960cd61f394fd52c28752b6d`）。

**手机（免电脑）**

装任意一个能查看应用签名信息的 App，选中 Keep Learning，
看「签名」里的 SHA-256 是否一致。

### 官方构建是怎么签出来的

签名材料（`keell-release.jks` 与 `keystore.properties`）**不在仓库里**，只由维护者本地持有。
仓库里的 Gradle 模板（`native/android/gradle-templates/app-build.gradle`）会自动读取
项目根目录的 `keystore.properties`：

- **有** `keystore.properties` → 用正式证书签 `release` 包
- **没有**（例如你 clone 后自己构建）→ 自动回退到 **debug 签名**

也就是说，你自己构建出来的 APK 一定是 debug 签名（指纹形如
`CN=Android Debug`），这很正常，不影响本地安装使用；
只是它不被视为官方包，也不能覆盖安装官方包（签名不同，Android 会拒绝）。

```bash
node tools/init-android.cjs      # 重建 android/ 工程
cd android && ./gradlew assembleRelease   # 有 keystore.properties 时出正式签名包
cd android && ./gradlew assembleDebug     # 调试包，始终 debug 签名
```

### 离线音频包（可选，官方 Release 不含）

官方发布包是 **lite 包**：仓库和 Release 都不含 MP3（避免再分发 Edge TTS 产物）。
需要离线单词/听力音频时，在本地生成后再构建：

```bash
node tools/gen-audio-pack.cjs --dry   # 检查 Python/edge-tts/ffmpeg 依赖
node tools/gen-audio-pack.cjs         # 生成到 assets/audio（可中断续跑）
node tools/build-android.cjs          # 本地带音频构建
```

生成的文件**不要提交 git、不要上传公开 Release**；Windows 用户可以直接双击 [生成音频包.bat](生成音频包.bat)，详见 [docs/36-离线音频包生成.md](docs/36-离线音频包生成.md)。

**修法**：
- `_onSelect()` 只设置 `selected.type`，**不再改动 `anTab`**
- 删掉两处 tab 拦截
- 改由 `_anPanel()` 按 `selected.type` 自动对齐 tab：
  划句（≥4 词）→ 显示长难句分析；划词（1–3 词）→ 显示词性翻译

- `Dict.get()` 返回 `[音标, 释义, 原词形]`——`d[0]` 是音标、`d[2]` 是**词形不是词性**

- **即时反馈**：对错判定 + 正确答案 + 听写命中率 + 未写出的词 + 原文译文对照
- 布局改为与四六级一致的左右分栏（左播放器+原文，右答题卡）

### 2. 听力播放改为整句连续朗读

**问题**：原来用 `_playWords()` 逐词调用 `speak()`，听起来一顿一顿的机械音，
完全不像真实考试。

**改法**：新增 `_playLines()`，每个**句子**作为一次 `speak()` 调用，句间 380ms 停顿
（接近真人换气），语调起伏由语音引擎自然产生。

- 词级高亮用 `onboundary`（charIndex → 定位词 span）
- 若浏览器不触发 `onboundary`，自动降级为句级高亮——**宁可粗一点，也不能读得断开**
- 对话按 `sp` 标注轮流男女声（M/W），实现分角色朗读

**顺带修的真 bug**：`Speech.init()` 只在 `DOMContentLoaded` 跑一次，
而 Chrome 的 `getVoices()` 是异步的（初始返回空数组），
部分平台不触发 `onvoiceschanged` → `Speech.voices` 永远为空 →
`pickVoice()` 返回 null → 整段朗读走进"静音模式"。
修法：加轮询兜底（最多 3 秒）+ `speak()` 前主动补一次加载。

另加**静音降级模式**：首句 1.5 秒内无响应即判定引擎不可用，
后续按字数等速推进（保持节奏感与高亮），并 toast 告知用户。

### 3. AI 深度解析固定全部维度

原先是「有数据才渲染，没数据整行消失」——用户看到的是残缺的解析，
误以为功能有问题。

现在**固定列出全部 8 个维度**，缺失的显式标注「本次未返回」/「无明显词根」：

音标 · 语境释义 · 常用搭配 · 词根词缀 · 近义词 · 反义词 · 近年常考 · 语法说明 · 例句

AI 提示词同步升级：
- 新增 `grammar` 字段（相关语法说明，2-4 句）
- 明确「**全部字段必填**，即使没内容也要给空数组，不允许省略」
- `collocation` 至少 2 条、`synonym`/`antonym` 各至少 1 条
- `max_tokens` 1100 → 1400

本地降级路径也返回完整字段（含 `grammar: ''`），保证结构一致。

功能本身可用（`AI.analyzeSentence` + `_anSent` + `_refreshPanel` 链路完整），

## 第十一轮修复（4 项）

### 1. 做题模式多题选中反馈丢失

## 第十二轮修复（6 项）

### 1. 评分「18/15」：得分超过满分

**根因是赋值顺序错了**：
```js
r.score.max = totalScore;                    // ← 先覆盖了 max
const ratio = r.score.total / r.score.max;   // ← 分母用新满分，分子还是旧满分
r.score.total = Math.round(ratio * totalScore * 10) / 10;
```
分母被换成新的满分（15），分子还是 AI 自报满分下的得分（18）→ ratio 被放大 → 结果超过满分。

**修法**：先用**原满分**算得分率，再等比缩放，并把 ratio 夹在 0~1：
```js
const oldMax = +r.score.max || 30;
const ratio = Math.max(0, Math.min(1, oldTotal / oldMax));
r.score.total = Math.round(ratio * newMax * 10) / 10;
r.score.max = newMax;
```

### 2. 评分有理有据：维度与总分关联

原来维度满分**硬编码 /15**，本题满分是 20 时就出现「总分 18/20 但维度 3/15 + 11/15 +…」这种对不上的情况。

现在：
- 显示「本题满分 20 分，得 18 分（得分率 90%）」，**明确写出满分是多少**
- 四维满分 = 总分满分 / 4
- 四维得分**按比例映射到总分**，并修正四舍五入误差，**保证四维之和严格等于总分**

实测：本题 15 分 → 得分 7（47%），四维各 3.8，合计 7，完全自洽。

### 3. 划线分析加发音按钮 + AI 解析含当前词

- 音标旁加「🔊 读」按钮，点击朗读当前划线词（`data-say`，复用现有朗读机制）
- AI 深度解析顶部新增**单词标题区**：大号显示当前单词 + 音标 + 发音按钮
  （原来只有音标和各维度，看不出在讲哪个词）

### 4. 切下一个词时自动关闭上一个 AI 解析

**根因**：划句路径（`_onSelect`）里清了 `aiInline/aiData/aiFolded`，
但**点词路径（`[data-w]` 委托）漏了**——上一个词的 AI 块一直挂着，看起来像"没切换"。

### 5. 长难句 tab 下划句无法分析

**根因**：`_pickedText()` 读的是 `this._firstW`，
而划选状态在**上一轮**已改挂到容器上（`ps._firstW`，因为段落与题目区是两个独立划选区域）。
两处不一致 → 划句永远取不到范围。

修法：`_pickedText` 改读 `ps._firstW`；并让划句后**自动跑一次分析**
（用户划完句的预期就是立刻看到解析，再点一次按钮会被当成"没生效"）。

### 6. AI 偶发失败加重试

偶发的"AI 调用失败"多数不是配置问题，而是**网络抖动、429 限流、5xx**。

新增 `AI.jsonRetry()`：
- **指数退避**重试：0.6s → 1.2s → 2.4s，最多 3 次
- 只对可重试错误重试（429 / 5xx / 网络 / 超时）
- **401/404 不重试**——配置错误重试也不会变好，只浪费时间
- 同时把 `TypeError` / "Failed to fetch" 转成明确的中文提示
  （用户遇到这类"有概率"的错，往往以为是 Key 或模型配错了）

### 7. 阅读篇幅扩写到考试标准

原来六级只有 91~149 词（真题约 400 词），太短。

扩写后（**只扩正文，不改题目**，保证题目与原文依据一致）：

## 第十三轮修复（7 项）

### 1+2. 听力高亮跑太快 + 句首第一个词发音残缺（同一根因）

**根因是兜底计时器估算过短**：
```js
const est = Math.max(2500, text.length * 95 / rate) + 1200;   // ← 95ms/字符
```
正常英文约 **180 词/分钟 ≈ 380ms/字符**，估算短了一半 →
句子还没读完就 `done()` 推进下一句 → **高亮跑在朗读前面**；
同时新一句的 `speak()` 会 `cancel()` 掉正在播的句子 → **下一句首词只听到后半段**。

**修法**：
- **兜底只在首句**做引擎探测（1.5s + 字符数×60）
- 后续句子用**极宽松兜底**（20s + 字符数×600），正常永不触发
- 真正的进度由 `onend` 驱动，兜底只在 `onend` 永不触发时兜底

同时把高亮定位从 `indexOf` 改为**预计算偏移量表**（`offsetTable`），
避免重复词、连字符（well-known）、缩写导致定位跳偏。

### 3. 划线发音按钮加防抖

`data-say` 与 `aiSay` 都改成**先 `Speech.stop()` 再 `speak()`**——
原来直接 `speak()`，连续点击会让多条朗读叠在一起变成噪音。

### 4. 长难句分析 + 保持选中态

**分析能力增强**：本地启发式重写，从原来「3 个字段 + 1 条要点」扩展为
7 类从句识别（让步/原因/条件/目的/定语/宾语/同位语）、并列与强调识别、
谓语动词定位、介词短语提取、句型判断（简单句/复合句/长句），
并保证至少给到 2 条具体要点。AI 失败时也会带上真实错误原因。

**保持选中**：原来划完句 2.5 秒后 `clear()` 移除高亮，用户正对照分析就没了。
改为**一直保持**，只有划下一句时才取消——且 `clear()` 从「只清当前容器」
改为**清所有容器**（跨段落划句时，上一句在另一个段落里，不清会残留）。

### 5. 阅读段落翻译折叠

修改模式下每段下方一个「📘 本段翻译」按钮，**默认收起**。
点开展开 → 调 `AI.translate()` 翻译该段 → 结果缓存，再次展开秒开不重复请求。
做题模式下不显示（避免泄题）。

新增 `AI.translate()`：用 `chat()` 而非 `json()`（翻译要纯文本）。

**两个必踩的坑**：
- `_reRenderPassage()` 里用的是**旧模板**（只有 `<p>` 没有翻译块），
  一重渲染就把翻译块冲掉 → 统一用同一个渲染函数
- 翻译是异步的，回来时会**覆盖用户之后的操作**（表现为"点了收起又自己弹开"）
  → 用 `_paraBusy` 记录段 key，翻译中**允许收起**（否则点不动），
  回来后检查 `_paraOpen.has(key)` 才应用结果

### 6. 新词学习自动发音 + 音标高亮

进入卡片（新词学习 / 复习）时**自动朗读当前单词**——
用户看到单词的第一反应就是读出来，先给声音再让他想意思。

统一走 `_sayCur()`：先 `stop` 再播，播放期间**音标高亮**（`.wcard-ph.on`）、
按钮点亮，播完复位。

### 7. 音标旁的发音标识

**根因**：`<svg class="ic">🔊</svg>` —— **emoji 放在 SVG 元素里不渲染**，
所以显示成空白方块。

## 第十四轮：发音自然度 + 排版（2 项）

### 1. 发音自然度（三层改进）

**先说技术边界**：浏览器内置的 Web Speech API **不支持 SSML**，
所以无法真正"注入情感"或精细控制语调。
但**完全平的 pitch + 恒定 rate 正是"人机感"的主要来源**，
因此从三个方向改进：

#### (1) 优先选神经网络音色

Windows 上常同时装有传统合成与神经网络合成两套音色：

| 音色 | 类型 | 自然度 |
|---|---|---|
| Microsoft Zira / David | 传统合成 | 机械感明显 |
| **Aria Neural / Jenny Neural / Guy Neural** | 神经网络 | 接近真人 |

原来的候选表 `Samantha` 排第一位，很可能挑到传统音色。
现在把神经网络音色排到前面，传统音色作为兜底。

#### (2) 按句意微调 pitch / rate

| 句型 | 判定 | pitch | rate |
|---|---|---|---|
| 疑问句 | `?` 结尾，或疑问词开头 | +5.5% | -2% |
| 感叹句 | 含 `!` | +3% | +5% |
| 列举句 | First/Second/Then/Finally 开头 | +1.5% | +3% |
| 复杂长句 | ≥3 个分句 | — | -1.5% |

**幅度控制在 ±6% 以内**——再大就会显得夸张，失去考试听感的稳重。
同时用 `Math.max/min` 夹住 pitch(0.6~1.6) 与 rate(0.5~2)，防止异常值。

#### (3) 句内按标点分句朗读（效果最明显）

新增 `splitClauses()`：按 `, ; : 、 —` 把句子切成小段，逐段朗读、段间留停顿。

| 标点 | 停顿 |
|---|---|
| `,` `，` | 90ms |
| `;` `；` `:` `：` | 130ms |
| `、` | 70ms |
| `—` `–` | 150ms |

短句（≤28 字符）不切分，避免把 `Hi.` 切得支离破碎。

句间停顿也按标点分级：
问号/叹号 420ms > 句号 360ms > 无标点 300ms > 逗号结尾 220ms。

**一个容易漏的细节**：分段朗读时 `onboundary` 的 `charIndex` 是**相对当前分句**的，
必须**加上前面分句的累计偏移**，否则每段都从 0 开始算，高亮会一直跳回句首。

### 2. 欢迎弹窗「生词本」换行

**根因**：`<b style="flex:none;width:62px">` 硬编码宽度。
「📒 生词本」四个字符（含 emoji）超过 62px 就被挤成两行。

**修法**：去掉固定宽度，改用 `white-space:nowrap` + `align-items:baseline`。
**用固定宽度对齐标签本身就是错的做法**——emoji、中英文混排时内容长度不可控。
让容器自己适应宽度才可靠。

## 第十五轮：听力高亮同步 + 翻译修复（3 项）

### 1. 高亮与语音不同步 / 部分词不亮 / 选句快过语音

**根因一：`onboundary` 并非在所有浏览器/语音包上都触发。**
一旦不触发，就没有任何词高亮；偶尔触发一两次，看起来就是"部分词闪一下"。

**修法：加时间轴兜底高亮**
按「字符数 ÷ 估算语速」自己推进词高亮，**一旦真实 `onboundary` 到达就立刻停掉兜底**、
切回精确定位。这样"有没有高亮"不再依赖浏览器是否支持该事件。

**根因二：引擎探测过早判死。**
`FIRST_PROBE` 原本只有 1.5 秒，而语音引擎首次合成常需 2~4 秒 →
误判为"引擎不可用" → 进入**静音逐句模式**（按字数推进，与真实语音必然不同步）。
这就是用户看到的「未检测到可用语音引擎」提示的来源。

**修法**：
- `FIRST_PROBE` 放宽到 `4500 + 字符数×200`
- 超时时**先看 `_bHit > 0`**：只要收到过边界事件就说明引擎在工作，只是这句慢
- 静音模式提示加上排查指引（「可在设置页检查系统语音」）

### 2. 点击播放加 2 秒缓冲

新增 `leadIn`（默认 2000ms）：点播放后**先把第一句标好**，等 2 秒再开口。
两个好处：语音引擎有准备时间（避免"点了没声"）；
眼睛能先找到第一句，不会有"先听见声音、眼睛还在找句子"的错位感。

### 3. 长难句翻译仍然失败

**根因是 JSON 字段顺序**：`cn`（翻译）和 `easy`（讲解）排在**最后两位**，
`max_tokens` 不够时被截断的正是这两个 → 表现为"句型、成分都有，唯独没有翻译"。

**修法（三层）**：
1. **把 `cn` 和 `easy` 提到提示词最前面**——被截断时优先保住最重要的内容
2. `max_tokens` 1200 → **2000**
3. **补译机制**：若返回结果里 `cn` 仍缺失或过短（<4 字），
   单独再发一次翻译请求（`max: 400`），标记 `cnFilled`

这样即使分析结果被截断，翻译也一定能拿到。

### 4. 语音与原文一致性

验证方式：对每一行比对 `dataset.say` 与该行所有词 span 拼接后的字符序列
（去标点后应完全相等）。**7 行全部匹配**——朗读内容与原文完全一致。

## 第十六轮：高亮同步 + 男声 + AI 配置（5 项）

### 1+4. 只有第一个词高亮 / 同名词同时高亮

**根因一：兜底定时器是所有分句共用的。**
`timer` 声明在分句循环外，每个新分句 `clearInterval(timer)` 会把**上一句的定时器清掉**，
两个循环互相打断 —— 表现就是「只有第一个词亮一下然后停住」。

**修法**：`myTimer` 改为**每个分句独立**的局部定时器，各自 `stopFallback()`。
同时 `const myBase = base` 在推进 `base` **之前捕获**，回调里只用 `myBase`
（原来在回调里现读 `base`，那时已经指向下一句，偏移全错）。

另外把原来「filter 猜」的 `wordsInClause` 换成**顺序扫描 + 边界判断**的 `inClause` ——
filter 会误匹配到全句其他位置的同名词。

**根因二：清理高亮只清当前句。**
原来 `words.forEach(remove)` 只清本句的词，下一句的残留高亮不会被清，
于是出现「两个拼写相同但位置不同的词同时高亮」。

**修法**：改成 `$$('.script-line .w.on').forEach(...)` **跨整篇清理**，
保证任一时刻**有且只有一个**词高亮。实测「同时最多高亮 = 1」。

### 2. 四级听力播放报错

定位到 `offsetTable` / `locate` 在重构后已无人调用（死代码），
且 `wordsInClause` 的范围计算会在 `base` 未累加时匹配到全句第一个词。
重写后一并删除死代码。

### 3. 系统缺英语语音包 → 静默失败

测试时发现：`allVoices` 有 3 个但 `voices` 为 0 —— 系统只装了中文音色。
用户场景同理：精简版 Windows 没装英语语音包时，点播放**完全没反应**，
用户会以为程序坏了。

**修法**：`Speech.speak()` 检测到无英文音色时弹窗，给出 Windows / macOS 的
安装步骤（重点推荐「英语（英国）」以贴近四六级音源）。

### 4. 男声默认音色

`MALE` 候选表把 **`Google UK English Male` 排到第一** —— 四六级听力录音多为英式男声，
这样默认音色最接近考试听感。缺该性别音色时切换会弹安装指引。

### 5. AI 配置持久化 + 余额提醒

**配置重复填写的原因**：Key 输入框是 `type=password` 且提示「本页不会显示」，
用户**无法确认自己配过没有**，于是反复重配。

**修法**：
- Key 框加「👁 显示 / 隐藏」按钮，可直接确认
- 已配置时显示绿色提示条：「配置已保存在本机，**下次打开无需重新配置**。
  只有更换接口地址或模型时才需要再改」
- 状态标签区分「已启用」与「**已配置（连接异常）**」

**余额提醒**：`friendlyErr` 原先把「余额不足」和「触发限流」混在 429 分支里，
用户看不出该充值还是该等待。现在拆成独立分支：
- 命中 `insufficient_balance` / 余额不足等关键词 → 弹**醒目模态框**指引充值（一次性去重）
- 真正的限流 → 提示「等一两分钟再试；若反复出现可能是额度用尽」

保存配置时重置提醒标记，充值后可再次触发。

## 第十七轮：听力逐词高亮修复（2 项）

### 1. 句首第一个词只读一半

**根因：`splitClauses()` 只按逗号切，不按句号切。**
像"I've had one for three years. I can drive both the truck and the van."
这种 100+ 字符的句子只切成 **1 段**，整段一次 `speak()`；
兜底高亮按「字符数 × 300ms」估时，一个词要亮好几秒 —— 听起来就是"卡在首词"。

**修法**：把 `. ! ? 。！？` 也加入切分点（停 200~220ms），
并在切分前保留「≤28 字符不切」规则（`Hi, there.` 切成两段会显得割裂）。
现在长句切成 29 / 40 字符两段，每段都能正常逐词推进。

### 2. 播放时只有首个词高亮

**根因（上一轮引入的）：`if (at < 0) break;`**
分句圈词时从 `p = myBase` 开始找，但循环每次都从**`words[0]`** 扫起。
第二段时 `words[0]`（"Hi"，在位置 0）已经在 `myBase` 之前，
`indexOf('Hi', myBase)` 必然返回 -1 → `break` → **整段的词全被丢掉**。

所以只有第一段的第一个词亮了，后面全黑。

**修法**：
- 循环开头先判断 `if (p >= myBase + cl.text.length) break;`
  （已越过本分句才停，这才是正确的终止条件）
- `indexOf` 返回 -1 时改为 **`continue`** 而不是 `break`
  （某个词因撇号/连字符差异找不到时，跳过它继续试下一个，
  不能把后面所有能匹配的词一起丢掉）

实测：全句词高亮覆盖率从 **1/10 → 10/10**。

### 3. 高亮时长改为按词长计算

原来用 `setInterval(estMs / 词数)` **均分**，
导致 "I" 和 "extraordinary" 亮一样久 —— 短词一闪而过、长词迟迟不换。

改为逐词 `setTimeout`，时长 = 该词字符数 × 300ms（最少 150ms），
首个词 60ms 内先亮起给即时反馈。

## 第十八轮：高亮速度 + 首词失音（2 项）

### 1. 高亮速度跟不上语音

**根因：单位换算错了。**
原代码 `const msPerChar = 300 / rate`，字面意思是「**每字符** 300ms」。
于是`Excuse`（7 字符）要亮 **2100ms** —— 音频早读完了，高亮还停在第一个词，
就是你看到的"听完了才高亮第二个词"。

**真实语速**：英文约 150 词/分钟 ≈ **每词 400ms**；
按平均词长 4.5 字符折算 ≈ **每字符 90ms**。

**修法**：`MS_PER_CHAR = 90 / rate`，并对单词时长夹逼到 **130~600ms**：
- `I` → 130ms（不拖沓）
- `Hi` → 180ms
- `Excuse` → 540ms
- `extraordinary` → 600ms（不卡住）

实测「高亮总时长 / 真实朗读估时」比值从远大于 1 降到 **0.94**，基本同步。

### 2. 句首第一个词失音

**根因：分句文本带前导空白。**
切分点保留标点，第二段常以 `", "` / `" "` 开头
（如 `" are you volunteering for..."`）。**Chrome 的语音合成对以空白开头的文本
会吞掉第一个音节**，听起来就是"首词只读了一半"。

**修法**：
```js
const speakText = cl.text.replace(/^[\s,;:.、，。；：]+/, '').replace(/\s+$/, '');
```
- 剥离前导空白与孤立标点
- **补偿被剥离的字符数**（`skipChars`），保证 `onboundary` 的 `charIndex` 仍能正确定位到词
- 剥离后若为空则跳过该段，防止 `speak('')` 卡住队列

实测剥离后首字符全部是字母（`H` / `a` / `I` / `N`）。

### 顺带修正

- `stopFallback()` 原用 `clearInterval`，但兜底高亮已改为 `setTimeout` 链 → 改为 `clearTimeout`
- 词高亮覆盖率实测 **10/10、16/16、7/7、15/15**（全句每个词都能轮到）

## 第三十五轮：刷新后"首次播放是人机声 + 首个词吞音"

用户实测两句话：①"刷新整个界面后首次直接点播放单句听力，默认女声是人机声，只有来回切换男女声后
才会用正常人声"；②"背单词的首个单词也会出现这个情况，而且会吞第一个词的发音"。

### 根因 1 · 首次播放用的是"只发布了 3 个本地音色"的半截列表
Edge 的云端神经音色是**异步发布**的：页面刚打开时 `getVoices()` 往往只返回 3 个本地 SAPI 音色
（Hazel / Susan / George），几十~几百毫秒后才补齐那 46 个云端音色。而 `Speech.init()` 原来写的是
`if (load()) return;` —— **第一次拿到非空列表就停止刷新**，也不再监听变化。于是"刷新后第一次播放"
只能在本地音色里挑 → 人机声；等一会儿（或来回切一下男女声、触发一次重绘/重取）之后列表才齐 → 正常。
背单词的首个词同理：卡片一渲染就朗读，正好落在这个窗口里。

修法：
- `init()` 改为**等到列表里出现期望的云端音色**（`_voicesReady()`，或等满 3 秒）才停止轮询；
- 新增 `_refreshVoices()`（与 init 同一过滤口径）与 `_voicesReady()`；
- `_pump()` 在选音色前先等列表齐全（最多 `VOICE_WAIT_MS = 1200ms`，每 100ms 刷新一次），
  列表一齐立刻继续 —— 首次播放不再用半截列表选音色；

### 根因 2 · 首个词吞音：引擎/音频设备冷启动

首次朗读的 pre-roll 也放宽到 `FIRST_PREROLL_MS = 200ms`，第二次起恢复原样（立即开口）。

## 第四十二轮：导入流水线改造（结构切批 + 原文位置 + 程序校验）

按用户方案把 AI 导入从「固定字数切段 + 紧凑 prompt + 递归二分」改成
**AI 识别结构、程序保完整性**。详细设计见 `docs/28-导入流水线-结构切批与校验.md`。

### 落地
1. **结构优先切批**（新增 `js/import-pipeline.js`）：先按 Section/Passage/Text/Questions N to M/Directions
   切结构块；同模块合并；4500 字符只作兜底上限，超长时按段落→题号行→句末拆，并标记
   `continuation`（前文只当上下文，禁止复制）。**不会再把 Passage 标题/正文/题目拆开**。
2. **原文位置**：PDF 提取保留每页区间 `{no,start,end}`；批次带 `[start,end)` 与 `pageStart/pageEnd`；
   TextRepair 改变文本长度时自动丢弃页码区间，避免位置错位。
3. **每批只处理同类结构**：每批只让 AI 输出本批模块（听力/阅读/写作），作文 Directions、
   阅读原文、选项都要求逐字复制；模块归属从 Part 大标题向下继承（不再把听力题并进阅读批）。
4. **程序侧完整性校验** `validateBatch`：
   - 题号对照原文 `Questions N to M`/编号行（兼容 "5 1." OCR 拆分）→ 漏题/多题直接报错；
   - 选项数量、答案下标、Section A 词库字母、Section B 段落字母、翻译原文、写作 prompt 长度；
   - 题干/选项在批次原文中定位不到 → 警告并计入覆盖率（AI 改写会被发现）。
5. **失败只修该批**：校验错误清单回传给 AI 定向重试一次；仍失败记入失败清单，不整卷重解析。
6. **缓存续跑**：成功批次按 `原文+模块+类型+prompt版本` 哈希缓存到
   `localStorage['keeplrn_import_cache_v1']`（≤40 批/约 800KB）；重跑同一份文件直接命中。
7. **考试类型证据核验**：evidence 必须在正文中能找到（逐字或 ≥8 字连续片段），
   否则 type 置空转人工确认，减少"AI 猜等级 + 编证据"误标。
8. **兼容兜底**：结构切批不足 2 批或任一步抛错 → 自动回退旧整卷切分（`_aiSplitLegacy`），
   新路径失败不会导致无法导入。

## 第四十九轮：听力吞音 / 切篇不断播 / 音色不统一（2026-10-22 真机反馈）

### 用户反馈（平板真机）
1. 四级对话**每句有吞音**，对话首词被吞；六级同样；
2. 点「下一段/下一篇」再播放时，**上一段原文和题干还在读**；
3. 四六级不同篇章的听力**音色不一样**。

### 根因
1. **音色不统一**：听力有的句子在预生成音频包（Sonia/Ryan），有的不在（Piper jenny/alan）；
   内置对话里部分句子走 pack、部分走本地，同一篇内都会跳。
2. **吞音（首词）**：两层原因
   - `AudioPackPlugin` 在 `start()` **之前**调用 `setPlaybackParams()`：本机机型上会丢掉起播几十~上百毫秒；
   - `LocalTtsPlugin` 写出的 WAV 几乎从第一个采样就开始说话，MediaPlayer 起播准备时间把首音切掉。
3. **切篇不停播**：`_playExamOrder` 的旧链只看 `this._playAbort`，而新播放一开始会把它重置成 `false`，
   旧链睡醒后“复活”，继续播上一段的题干；`prev/next` 也只调用 `Speech.stop()`，没有作废旧会话。

### 修复
1. **听力统一音色**：`Speech.speak` 新增 `listening:true` 场景——只要有离线语音库就由它接管（jenny/alan），
   音频包只服务单词语音；`prefetch` 同样走本地预取。所有听力调用（原文/题干/复述/结尾语）都打上该标记。
2. **吞音**：
   - `AudioPackPlugin`：1.0 倍速不再调用 `setPlaybackParams`，直接 `start()`；变速时才在 start 之后设置；
   - `LocalTtsPlugin`：写 WAV 时补 **150ms 前导 + 100ms 尾部静音**，缓存键升级 `piper-v2`（旧 WAV 自然失效）。
3. **切篇/切句必停**：新增 `_playSession` 会话号（play/循环每次换新；stop/prev/next 都换新），
   `_playExamOrder` 每一步都用它自检；`prev/next` 改为调用 `stopHL()`。

### 验证
- `check-local-tts` 扩到 10 项（新增“听力场景即使有系统音色也走本地”“非听力场景不抢占”）；
- 真机 1.1.31/1.1.32（最终安装版 1.1.32-test / code 56）：对话/长篇**全部**由 `LocalTts.synthesize` + `AudioPack.play(filePath)` 播放，
  不再出现 `audio/sentences/...` 的音频包路径；男女声按 sp 在 jenny/alan 间切换；
- 新合成 WAV 前 150ms 为静音（RMS 0–150ms = 0.0000，250ms 后开始有声），缓存键 = `sha1(text|voice|piper-v2)`；
- 真机切篇实测（1.1.32 / code 56）：播放中切「下一段」前 4 秒共 6 次音频调用，切换后 10 秒 **0 次**
  （旧实现会继续读上一段的下一句/题干）；
- 最终包：**1.1.32-test（versionCode 56），361,236,902 字节**；全量回归 **39 套 / 424 项通过 / 4 项失败**

2. 「学习设置 → 每日新词目标」填 30，但学习时每轮仍只出 10 个新词，设定像没用；
3. 翻译、写作要增加记忆功能，只记最近 5 条。

### 根因
1. **熟悉循环**：「熟悉 / 跳过 / 只看词条详情」只改引擎状态，**不消费当前轮的执行队列**；
   `ViewVocab._advance()` 又用 `round.slots` 整体重建队列 → 刚看过的词位仍在队首，
   `qi` 指回它，于是无限重复。真机与 `work/repro-familiar.cjs` 均稳定复现
   （修复前：第 1 次"熟悉→下一个"后队列变成 [当前词, 当前词, …]）。
2. **日目标无效**：`_selectSlots` 只看 `NEW_PER_ROUND.max`，完全不读 `settings.dailyNew`；
   `dailyNewCount` 只累计不设限。且词书页「今日新词」取 `stats.daily.words`（把复习/抽检/拼写答对也算进去），
   日目标会被提前误判完成。

### 修复
1. **引擎**：新增 `consumeSlot(wordId, senseId, slotObj)`，按对象身份从当前轮队列移除词位
   （不误删同词的 retry 重考位，且该轮清空时正常结算收尾）；`_advance()` 推进前统一消费当前词位
   → 熟悉 / 跳过 / 详情→下一个 三条路径都不再回到同一个词。
2. **日目标生效，且达标后可以继续学新词**：`startRound({dailyNewTarget})` 由 UI 传入 `settings.dailyNew`；
   未达标时每轮新词数 = min(每轮上限 10, 本词书剩余, 今日剩余额度)（目标 30 = 10+10+10；今天剩 5 个额度就只出 5 个）；
   **达到目标后仍可继续加学新词**（每轮 ≤10，轮上带 `round.newOverGoal`），不强制改复习——复习有独立入口与到期词；
   只有词书没有 L0 新词时才回退复习轮；换轮时把上一轮未学的新词位从 `dailyNewCount` 扣回。
3. **UI**：词书页「今日新词 X / 目标」（中途退出时扣掉本轮还没轮到的新词位，不虚高）；
   达标后按钮变「继续学习新单词 → 再加 N 词」；学习页 HUD 加「今日新词 X/N」实时进度；
   设置弹窗补一句目标口径说明（每轮最多 10 个、分几轮完成、达标可继续加学）。
4. **首页口径统一**：「今日新学单词」= 引擎新词数（与词书页同一口径，并扣掉未轮到的新词位；
   引擎不可用时回落旧统计）；卡片下加一句说明"只算新词，不含复习/抽检/拼写答对"，
   不再出现"今日 39 词 vs 目标 30"的矛盾。
5. **翻译/写作记忆**：两页各自记住最近 5 条输入（`Store.d.translationHistory / writingHistory`），
   输入 800ms 防抖自动落盘，提交/保存草稿/换题/切 tab/离开页面前 flush；工具栏「🕘 最近记录」弹窗可
   查看时间/题目/前 30 字并一键恢复（不自动提交），也可清空；数据只存本机。

## 多端访问（历史记录；正式支持见顶部矩阵）

> ⚠️ 下面是早期开发记录，**不代表正式支持**。
> 官方只支持 **Windows 10/11** 和 **Android 平板 APK**；Android 手机、iPad/iPhone、macOS 均在制作中，暂无构建。

### 局域网访问（平板/其他设备）

1. 电脑和手机连同一个 Wi-Fi；
2. 双击桌面图标启动（等价于 `node serve.js 8777 --open`）；
3. 启动窗口会打印一行 `局域网: http://192.168.x.x:8777`，手机浏览器输入这个地址；
4. 手机浏览器菜单 →「添加到主屏幕」，之后就像 App 一样全屏打开。

只想本机用、不想暴露给局域网：`node serve.js 8777 --local`（或设环境变量 `KEEP_LEARNING_HOST=127.0.0.1`）。
第一次启动如果 Windows 弹防火墙提示，需要允许"专用网络"，否则手机连不上。

### 三种形态

| 设备 | 导航 | 布局 |
|---|---|---|
| 手机（<600px，未适配，不提供支持） | 底部 5 Tab：今日 / 单词 / 听力 / 读写 / 我的 | 单列、卡片、全屏学习 |
| 平板（600–1099px） | 左侧图标 Rail（76px，图标+小字） | 单列/双列自适应 |
| 电脑（≥1100px） | 原来的 212px 侧栏（可收起） | 多列工作台，不变 |

「读写」聚合了阅读 / 写作 / 翻译，「我的」聚合了生词本 / 统计 / 设置 / 树园入口——底部 Tab 只有 5 个位置。

### PWA 与离线

- Service Worker 只在 **https** 或 **localhost / 127.0.0.1** 注册。局域网 `http://IP:8777` 可以正常使用，但不能离线。
- 电脑上打开 `http://127.0.0.1:8777`：地址栏右侧「安装」→ 安装成独立窗口，之后断网也能打开已缓存的页面与词书。
- 手机要真正离线，需要 HTTPS 部署（例如 Cloudflare Pages / Vercel），本机服务不提供 HTTPS。

### 平板独立运行（纯静态 PWA）

- `../keeplearning-multidevice/KeepLearning-静态版` 是去掉服务端的静态版本，可部署到 Cloudflare Pages / Netlify 等 HTTPS 静态托管；
- 平板安装成 PWA 后可离线使用；语音走浏览器自带 `speechSynthesis`（系统语音），不依赖电脑；
- 导入的真题存本机并随备份走；真人词典音频没有服务端，默认关闭，系统语音不受影响；
- 详细部署与语音设置见静态版目录里的 `部署说明.md`。

### 数据

- 学习进度保存在各自浏览器 localStorage（`keeplrn_v1`）。
- 换设备：设置 → 数据管理 → 导出备份；在另一台设备选 **仅导入学习进度**（保留本机设置/AI Key），或选导入备份做完整覆盖。
